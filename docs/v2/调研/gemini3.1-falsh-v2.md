# Agent 架构基准测试与优化分析 (gemini3.1-falsh-v2)

## 1. 架构概览
本报告将当前 `agent-platform` 架构与行业领先的开源实现进行了对比，以识别战略优化方向，重点关注 Agent 运行时、上下文管理和记忆持久化。

| 项目 | 核心原型 | 关键差异化特性 |
| :--- | :--- | :--- |
| **OpenClaw** | 网关中心化 | 星型路由 |
| **HermesAgent** | 学习循环 | Agent 自主编写 Skill |
| **Claude Code** | 分层框架 | 确定性 Hook |
| **Qwen-Coder** | 多 Agent 团队 | 编排与守望机制 |
| **Codex (CLI)** | 工作树编排 | 并行任务隔离 |

## 2. 差距分析与优化机会

### A. Skill 调用
*   **当前状态：** 主要为静态的 Skill 定义。
*   **优化建议：** 实现**自主 Skill 进化**（类似于 HermesAgent）。当 Agent 在成功任务中识别出重复模式时，应建议一个新的 Skill 定义（Markdown 格式），经人工审核后纳入 `/source/agent-platform/agent-biz/skill/`。

### B. 用户对话与记忆
*   **当前状态：** 可能为基础的会话级历史记录。
*   **优化建议：**
    *   **上下文压缩：** 采用 Claude Code 使用的“上下文窗口战争”四阶段方法（折叠 → 剪裁 → 微压缩 → 自动摘要）。
    *   **知识图谱记忆：** 超越简单的文本日志。实现基于 MCP 的索引，将架构决策（决策、反模式、项目规则）与瞬时聊天日志分开存储。

### C. 执行与可靠性
*   **当前状态：** 集成化单体/平台。
*   **优化建议：** 引入**确定性 Hook**（Claude Code 模式）。将关键的、非 LLM 逻辑（如仓库校验、Lint 检查）移入预定义的、不依赖 LLM 推理的可执行 Hook 中。

## 3. `agent-platform` 路线图建议

1.  **第一阶段（可靠性）：** 将非 LLM 安全检查提取到 `agent-infra` 中作为确定性 Hook。
2.  **第二阶段（上下文）：** 重构对话状态机，支持长会话的自动上下文摘要。
3.  **第三阶段（进化）：** 实现反馈循环，让 Agent 根据任务成功指标建议新的 `SKILL.md` 定义。
