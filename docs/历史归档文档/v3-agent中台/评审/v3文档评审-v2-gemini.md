# V3 Agent 中台文档评审报告 (Gemini-v2)

**评审日期**：2026-05-19
**评审对象**：`docs/v3-agent中台/` 核心文档 (排除 `评审/` 目录)
**核心焦点**：AI Native 编程模式、架构一致性、契约完整性、小工程闭环

## 1. 总体评价

HTAM Agent Platform V3 的文档系统已经从单纯的“产品技术文档”演进为一套**面向 AI Agent 的执行协议**。其核心优势在于：
- **边界极致清晰**：通过 `owned modules/files` 和 `contract slice` 解决了多 Agent 并行开发时的冲突与漂移问题。
- **验收闭环严密**：L0-L5 的验收等级不仅是质量要求，更是 AI 任务完成定义的硬性指标。
- **知识上下文可追溯**：强制要求 AI 引用 `source/fork_source` 中的具体符号，有效降低了 AI 生成幻觉代码的概率，确保了工程的严谨性。

## 2. AI Native 交付规约专项评审

### 2.1 任务隔离与阅读路径 (优秀)
- **亮点**：`必须阅读` 规则通过限定 AI 的感知范围，有效控制了上下文窗口（Token 消耗）并防止了“跨工程干扰”。这在处理复杂工程时是保持 AI 专注度的核心手段。
- **观察**：文档目录结构（如 `ai-tasks/poc-*/TASK-*/`）非常适合 Agent 进行文件定位和增量读写。

### 2.2 契约驱动开发 (优秀)
- **亮点**：`contract-notes.md` 的引入非常巧妙。它充当了局部契约的“缓冲区”，解决了 AI 在并行开发时频繁修改全局基线导致冲突的难题。
- **建议**：在 `06-AI-Native交付规约.md` 中，可以增加对 `contract-notes.md` 格式的更强制性要求，例如必须包含“与原有实现/开源项目的具体代码差异对比表”。

### 2.3 Owned Files 约束 (核心优势)
- **亮点**：明确禁止“顺手修”和“跨模块修改”。这是大型 AI 协作项目的“保命符”，确保了变更的原子性和可审计性。
- **评审意见**：该规约非常成熟，可以直接作为后续所有 AI 任务的 Meta-Prompt 基础。

## 3. 技术架构与核心链路评审

### 3.1 架构一致性
- **模块分层**：`agent-domain` 到 `agent-boot` 的依赖方向清晰，符合 Clean Architecture 原则。
- **双持久化策略**：MyBatis-Plus 处理 CRUD，R2DBC 处理高频 SSE checkpoint。这一方案在 `ADR-0002` 中论证充分，解决了传统持久化框架在流式场景下的性能瓶颈。

### 3.2 运行时路由逻辑
- **安全性**：沙箱路由基于“动作风险”判定而非“Agent 类型”，逻辑严密。
- **架构定力**：坚持不自研 ReAct 循环，而是通过适配器模式复用 `agentscope-java`，这种“不重新发明轮子”的思路非常适合中台定位。

### 3.3 图片型输入 (input-ocr) 预留
- **设计思路**：将 OCR 视为输入预处理能力 (input-preprocessor)，通过 `DerivedContext` 注入对话上下文。这种解耦设计允许主模型在非多模态的情况下依然能处理富媒体输入。
- **前瞻性**：文档中对 `sourceLocator` (页码、坐标等) 的预留显示了对复杂文档解析场景的深度思考。

## 4. 契约与数据模型评审

### 4.1 SSE Envelope & Sequence
- **稳定性**：`sequence` 单调递增和 `eventId` 去重机制是流式对话可靠性的保障。
- **改进建议**：在 `03-API-SSE-运行时契约-全局基线.md` 中，建议增加对 `assistant.thinking.delta` 阶段的超时处理约定。

### 4.2 数据切片 (EPIC-V3-A)
- **评审意见**：`02-工程契约切片.md` 准确定义了 `chat-minimal` 的最小数据集。通过显式列出“暂不实现”的表，有效防止了 AI 在初期开发时过度设计。

## 5. 测试与验收策略评审

### 5.1 验收等级 (L0-L5)
- **亮点**：将“真实链路验证”作为 L5 等级，并引入 `testRunId` 隔离，这是 AI Native 开发中防止测试环境污染的关键。
- **观察**：Playwright UI E2E 的强制要求确保了 AI 不会只修好 API 而搞挂页面。

## 6. 综合改进建议 (Actionable Insights)

1.  **自查脚本化**：建议在 `07-开发规范与本地环境.md` 中增加一套专门给 AI 使用的“自查脚本清单”（如：`check-dependency.sh`、`validate-flyway.sh`），让 AI 在生成 `handoff.md` 前能进行自动化的 L2 级预校验。
2.  **契约合并工作流**：目前从 `contract-notes.md` 合并到全局基线主要依靠“主 Agent 或 Review Agent”。建议在 `06-AI-Native交付规约.md` 中细化合并冲突时的决策树。
3.  **OCR 派生文本治理**：`DerivedContext` 可能包含长文本。建议在后续 `input-ocr` 小工程设计中增加针对 OCR 文本的“审计标记”和“敏感字段自动脱敏”规则。

---

**评审结论**：**通过**。
当前文档系统已经形成了高度结构化、职责明确、验收标准清晰的闭环体系，完全具备指导 AI Agent 开展 `chat-minimal` (EPIC-V3-A) 开发任务的能力。
