# 数据模型与安全审计

冻结状态：本文是 V3 数据模型 / 安全 / 审计全局候选基线，不再要求人工一次性评审完整 V3 数据模型。真实开发只冻结当前小工程 contract slice；首个冻结切片是 `EPIC-V3-A chat-minimal`，详见 `工程迭代/01-chat-minimal/02-工程契约切片.md`。未进入当前小工程的数据对象、状态和审计场景保留为后续候选契约，不能作为 `chat-minimal` 的验收门禁。

## 1. 数据域

V3 数据域：

```text
User / Role / Permission
Agent / AgentVersion / AgentTag
ExternalAgent
Session / Message / Attachment / DerivedContext
Memory
Provider / Model
Capability / MCP / Skill / Tool
Run / Span / Audit
Task / TaskResult
Workflow / WorkflowRun
```

租户边界：

- V3 POC 默认单组织 / 单租户部署，不在 POC-1/POC-2 强制实现完整多租户组织树。
- 所有用户侧业务数据必须至少带 `userId` 或等价归属字段。
- 可复用的 Agent、Capability、Provider、Workflow、TaskTemplate 必须带可见范围或授权关系。
- 后续引入 `tenantId` 时只能作为追加字段和查询条件，不得破坏当前 `userId`、授权关系和审计链路。

E2E 数据边界：

- 所有 E2E 创建的数据必须带 `testRunId`，可放在独立字段或 `metadata.testRunId`。
- 清理任务只能清理带相同 `testRunId` 的数据，不允许按模糊名称清理真实数据。
- `testRunId` 必须能关联 User、Agent、Session、Message、Run、Task、WorkflowRun、Audit 中的测试数据。

`metadata` 字段约定：

- `metadata` 必须是 JSON object，不允许保存裸字符串、数组或非结构化长文本。
- key 使用 camelCase，例如 `testRunId`、`sourceLocator`、`clientVersion`。
- 密钥、token、数据库密码、外部 Agent 凭据、原始敏感响应和图片原件引用不得写入 `metadata`。
- 可查询、可过滤、参与权限或清理的数据优先使用显式列；`test_run_id` 在 E2E 关键表中优先作为显式列，`metadata.testRunId` 只作为补充。
- 单条 `metadata` 建议不超过 16KB；超过该限制的结构化内容应拆到业务表、对象存储或派生上下文。
- `metadata` 中的测试、调试、来源字段不得改变业务状态机和权限判断。

### 3.2 流式与观测最低字段语义

`agent_message_checkpoint` 用于 SSE 断线恢复和 final flush 收敛，不是普通历史消息表。

最低字段：

```text

run_id
message_id
event_id
sequence
event_type
payload_json
```

约束：

- `event_id` 对应 SSE envelope 的 `eventId`，同一 run 内必须可用于恢复定位和去重。

- `payload_json` 保存对应 `event_type` 的平台 SSE envelope `payload` 结构，不保存未脱敏 runtime raw。
- `accumulated_content` 是当前 assistant 最终正文的累计快照，不是本次 delta；thinking 内容默认不混入该字段。

### 3.3 数据模型参考依据要求

新增或调整数据模型、表结构、DTO、状态枚举、索引和关系时，任务必须在对应 `contract-notes.md` 中记录参考依据。

最低记录项：

- 参考项目、版本 / commit / 文档版本。
- 源码文件、DDL、entity、schema、API response、官方文档 URL 或本地历史实现路径。
- 实际参考的 table / entity / DTO / schema / field / enum / relation / index。
- 本项目采纳的字段、状态、关系或约束。
- 本项目不采纳的字段、状态、关系或约束，以及原因。
- 与 V3 当前模型的差异、迁移影响和测试要求。

规则：

- 数据模型设计不能只写“参考 Dify / Open WebUI / Hermes / AgentScope”等泛泛来源。
- 若开源项目只有概念参考，没有可直接映射的数据模型，必须写明“仅概念参考”，并列出 V3 自定义字段的理由。
- 涉及用户数据、附件、OCR 派生上下文、工具参数、审计 raw 数据时，必须同时说明脱敏、权限和保留边界。

## 4. Agent 数据约束

`agent_definition` 是界面化配置 Agent 的核心表，不是代码注册表。

关键字段：

```text
agent_id
name
description
icon
agent_type configured/external
status
audit_status
system_prompt
default_provider_id
default_model_id
memory_policy
visibility_scope
runtime_type
metadata
```

约束：

- 新增通用配置 Agent 不应要求新增 Java 类。
- Agent 分类优先采用标签化模型，不使用单一业务域作为唯一归属。
- 外部复杂 Agent 必须有输入输出契约、风险等级、负责人和授权范围。
- 明文密钥不写入 Agent 定义，只保存密钥引用。
- `runtime_type` 只表达 Agent 默认运行偏好或运行约束，例如 `agentscope`、`sandbox`、`hermes`、`disabled`；实际执行使用的 runtime 以 `RuntimeCapabilityPlan.runtimeType` 为准。
- `metadata` 只能保存非敏感扩展信息；密钥、token、数据库密码和原始敏感响应必须使用安全引用或审计脱敏摘要。

`visibility_scope` 最小枚举：

```text
private
granted_users
role_scope
public_enabled
```

语义：

- `private`：仅创建者或管理员可见。
- `granted_users`：通过 `agent_user_grant` 授权给指定用户。
- `role_scope`：通过角色、权限或组织范围授权。
- `public_enabled`：对所有已登录用户可见，但仍要求 Agent enabled、审核通过和 Capability gate 通过。
- 可见范围只解决“能否看到或选择 Agent”，不替代 Capability 授权、runtime 风险判定或审计规则。

`agent_tag` 最低字段：

```text
tag_id
tag_group domain/scenario/task_intent/output_form/input_context/technical_capability/audience
code
name
description
status
sort_order
metadata
```

`agent_definition_tag` 最低字段：

```text
agent_id
tag_id
is_primary
source manual/system
```

标签约束：

- 标签只用于检索、筛选、推荐和展示，不作为权限、风险或能力授权的事实来源。
- `audience` 只表达推荐人群；可见范围仍以 `visibility_scope`、`agent_user_grant` 和角色权限为准。
- `technical_capability` 只表达能力摘要；实际 MCP / Skill / Tool 绑定仍以 `agent_capability_binding` 和 Capability gate 为准。
- `agent_type`、`status`、`audit_status`、`riskLevel` 不进入普通标签体系，避免筛选标签和治理状态混淆。
- 标签 `code` 应稳定，`name` 可按展示文案调整；同一 `tag_group` 内 `code` 唯一。

### 4.1 输入附件与 OCR 派生上下文候选

图片型输入和 OCR 不要求主对话模型具备多模态能力。平台应把独立图片、包含图片的上传文件、文件内嵌图片、扫描页或页面渲染区域作为可追溯输入资产治理，再通过受控 OCR / input-preprocessor 生成 `DerivedContext`，供非多模态主模型读取。

`agent_message_attachment` 最低字段：

```text
attachment_id
parent_attachment_id
message_id
session_id
user_id
type
mime_type
size_bytes
storage_ref
sha256
source_type uploaded_image/uploaded_file/embedded_image/scanned_page/rendered_page
source_locator_json
content_hints_json
status uploaded/processing/ready/failed/deleted
created_at
metadata
```

`agent_input_derived_context` 最低字段：

```text
derived_context_id
attachment_id
message_id
session_id
user_id
source_type uploaded_image/embedded_image/scanned_page/rendered_page
source_locator_json
processor_type ocr
provider_id
model_id
content_text
content_json
confidence
status processing/ready/failed
trace_id
created_at
metadata
```

约束：

- 附件和派生上下文必须带用户归属和会话归属，查询必须经过用户权限或管理端权限过滤。
- 文件内嵌图片、扫描页或页面渲染区域必须保留 `parent_attachment_id` 或等价原文件引用，并通过 `source_locator_json` 记录页码、sheet、slide、段落、图片序号、坐标区域等来源定位。
- `storage_ref` 只保存受控存储引用，不在业务表、日志、测试报告或错误响应中写入外部可访问下载地址。
- OCR 文本和结构化识别结果按用户输入数据治理，可能包含敏感信息；普通日志和审计摘要只能保存脱敏摘要。
- OCR provider、model、processor 版本和 traceId 必须可追溯，便于后续复核识别来源。
- E2E 附件和 OCR 数据必须支持 `testRunId` 隔离和清理。
- 该数据对象是后续候选契约，只有进入对应小工程 contract slice 后才成为实现和验收门禁。

## 7. MyBatis-Plus 边界

`repo-mybatis` 负责：

- 普通 CRUD。
- 后台配置。
- 历史查询。
- 分页查询。
- Agent、Capability、Provider、Session、Message、Run、Span 的常规读写。

约束：

- 不做逐 token/chunk 同步写入。
- 不直接服务 SSE 高频 checkpoint。
- 不被 biz/admin 直接调用，必须通过 `repo-spi`。
- MyBatis-Plus 可以读取 R2DBC final flush 后的历史结果，但不负责 stream checkpoint 的高频写入。
- MyBatis-Plus 查询必须带用户归属、授权或管理端权限过滤，不能默认全表可见。

## 8. R2DBC 边界

`repo-r2dbc-stream` 负责：

- SSE checkpoint。
- assistant message 累积内容更新。
- run/span/message final flush。
- 流式状态更新。
- 幂等 sequence 写入。

约束：

- 只处理流式高频写入相关端口。
- 写入结果必须能被 MyBatis 历史查询读取。
- 不和 MyBatis 做跨技术事务。
- 使用 runId、messageId、spanId、sequence 做幂等。
- checkpoint 写入失败必须记录为可观测错误，不允许静默吞掉。
- final flush 必须把最终 message/run/span 状态收敛到 MyBatis 历史查询可见的数据形态。
- R2DBC 端口不承载普通后台 CRUD、Agent 配置和权限配置。

## 9. 安全原则

- 默认拒绝，显式授权。
- 用户数据隔离优先于功能便利。
- 高风险能力必须经过 Capability gate。
- 图片型输入 OCR、文档解析、表格解析等输入预处理能力也必须经过 Capability gate；文档解析发现的内嵌图片同样需要受控 OCR 授权。
- 所有工具调用、外部 Agent 调用、高风险操作必须审计。
- 密钥只保存引用，不进入日志、文档、测试、PR 描述。
- 普通用户只看必要摘要，敏感参数、原始响应、图片原件、包含图片的上传文件、文件内嵌图片和 OCR 原文按权限查看。

## 10. 权限模型

权限判断至少包含：

```text
UserContext
AgentGrant
CapabilityGrant
VisibilityScope
RiskLevel
RuntimeEnvironment
```

Agent 使用必须满足：

- Agent enabled。
- Agent 审核通过。
- 用户有可见或使用权限。
- Agent 绑定能力可用。
- Capability gate 通过。

工作流执行必须满足：

- 用户有 workflow 使用权限。
- workflow 已发布且启用。
- 节点 Agent 可用。
- 用户或 workflow 有节点 Agent 调用权限。
- 节点 Capability gate 通过。

## 11. Capability Gate

Capability gate 输入：

```text
userId
agentId
sessionId
capabilityId
riskLevel
requestedRuntime
attachmentTypes
inputPreprocessors
environment
```

输出：

```text
allow
denyReason
runtimeType
allowedInputPreprocessors
attachmentPolicy
auditRequired
```

风险等级：

```text
low
medium
high
critical
```

默认策略：

- 未审核、未授权、已禁用、环境不可用的 capability 默认拒绝。
- `low` 可进入普通 `runtime-agentscope`，但仍必须受 Agent 白名单和用户授权约束。
- `medium` 默认需要审计，可按配置进入普通 runtime、sandbox 或 disabled。
- `high` / `critical` 默认不得进入普通 ReActAgent，必须进入 `runtime-sandbox` 或 `disabled`。
- 沙箱判定按本次执行动作风险决定，不按通用 Agent / 外部复杂 Agent 类型决定。
- Shell、Python、Browser 自动化、文件写入、系统命令等系统级动作必须进入 `runtime-sandbox` 或 `disabled`。
- OCR / input-preprocessor 默认按独立 capability 授权；未审核、未授权或 provider 不可用时，不得解析附件中的图片型输入。
- 发邮件、修改业务数据、提交审批、触发支付、写外部业务系统等真实业务副作用动作不进入 V3 当前范围，后续作为独立优化项设计。
- sandbox 未配置或健康检查失败时返回 runtime unavailable，不允许静默降级。

禁止：

- 未审核能力进入 runtime。
- 未授权能力进入 AgentScope。
- 平台通过关键词绕过 AgentScope 触发工具。
- 高危脚本、浏览器自动化、文件写入或系统命令进入普通 ReActAgent。
- 未授权 OCR / input-preprocessor 读取图片型输入，或把图片原件、文件内嵌图片透传给非多模态主模型。
- 真实业务副作用动作进入 V3 当前 runtime。

## 12. 审计模型

审计对象：

- 登录。
- Agent 配置变更。
- Capability 注册、审核、启停。
- Provider 配置变更。
- Chat run。
- Attachment upload。
- OCR / input-preprocessor 调用。
- Tool/MCP/Skill 调用。
- 外部复杂 Agent 调用。
- 工作流发布和执行。
- 高风险沙箱执行。


日志和错误响应必须脱敏。

审计约束：

- `traceId` 必须贯穿 HTTP、SSE、Run/Span 和 Audit。
- 高风险工具、外部 Agent、Provider 配置、权限变更和 Capability 审核必须写审计。
- 审计日志不得保存明文密钥、token、数据库密码、外部 Agent endpoint 明文凭据或完整敏感工具参数。
- 普通用户只能看到脱敏摘要；管理员查看原始参数也必须受权限控制并留下审计。
- 审计写入失败不能阻断低风险查询，但必须阻断高风险执行或记录为安全告警，具体策略由后续 `platform-observability` / `platform-security` 任务细化。

审计保留策略：

- POC 阶段不做自动清理和归档，避免误删人工复核证据。
- E2E 审计数据必须可通过 `test_run_id` 或等价测试标记清理。
- 生产保留期、归档、脱敏导出和冷存储策略由后续 hardening / CI 小工程冻结。
