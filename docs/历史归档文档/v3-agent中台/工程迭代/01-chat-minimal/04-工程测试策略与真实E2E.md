# 工程测试策略与真实 E2E

## 1. 目标验收

`chat-minimal` 目标验收等级为 L5。

全局测试规则见：

```text
docs/v3-agent中台/05-测试策略与验收等级-全局基线.md
```

## 2. L1 验收

后端：

```bash
cd source/v3-agent-platform
mvn test
```

必须覆盖：

- domain 状态枚举和值对象。
- agent-api DTO、SSE envelope、错误码和请求 / 响应结构。
- runtime-spi 契约。
- repo-spi 契约。

## 3. L2 验收

后端：

```bash
cd source/v3-agent-platform
mvn test
```

当前 POC-1/POC-2 尚未创建 `integration` profile；默认 `mvn test` 已承载模块编译、单元测试、API/SSE E2E 和架构边界测试。后续引入真实 PostgreSQL / R2DBC / Testcontainers 时，再新增 `integration` profile。

必须覆盖：

- Maven 多模块骨架。
- architecture test。
- 模块依赖方向。
- 仓储端口 CRUD 语义。
- checkpoint / final flush 语义。
- 历史消息读取。
- 最小用户身份和 Agent 授权校验。
- Capability gate stub 拒绝未授权 Agent 或未审核 capability。
- Provider / Model 初始化数据只保存密钥引用，不暴露明文。
- 默认 Agent 可追溯到初始 `agent_version`。

## 4. L3 验收

API/SSE E2E：

- 创建会话。
- 查询 Agent 标签分组。
- 按单个标签过滤 Agent 列表。
- 发送消息。
- SSE 接收 `run.started`、`assistant.delta`、`run.completed`。
- `Last-Event-ID` 断线恢复。
- 停止生成。
- 重新生成。
- 编辑重发。
- Session busy。
- `AUTH_REQUIRED` -> 401。
- `VALIDATION_FAILED` -> 400。
- Agent 未授权。
- Capability 未审核。
- `RUN_NOT_FOUND` / `STREAM_RESUME_FAILED`。
- Run / Span 查询。

## 5. L4 验收

Playwright UI E2E：

- 打开 Chat 页面。
- 通过标签筛选并选择 Agent。
- 新建会话。
- 输入消息并发送。
- 页面看到流式输出。
- 停止生成。
- 编辑历史消息并重发。
- 查看执行详情。

## 6. L5 验收

`.env` 完整时运行真实链路：

- 真实 LLM。
- 真实 AgentScope Java ReActAgent。
- 真实 PostgreSQL。
- 真实 SSE。
- 真实前端页面。

LLM provider 最低能力：

- 必须支持 streaming 输出。
- 必须能被 AgentScope Java ReActAgent 调用。
- 工具调用能力在 `chat-minimal` 中不是 L5 必选项；只有任务单要求验证工具路径时才强制 provider 支持 tool calling。
- 模型、base URL 和密钥引用只来自 `.env` 或本地安全配置，不写入测试报告。

降级口径：

- 如果 `.env` 不存在，可以跳过 L5，但最终交付必须说明原因和剩余风险。
- 如果真实 PostgreSQL / R2DBC adapter 尚未完成，最终交付也必须标记 L5 persistence pending，不能用内存仓储替代真实持久化验收。
- 如果 `.env` 存在但 provider 因网络、配额、模型不可用或认证失败导致真实调用失败，不得静默改成 mock 通过；应报告 L5 failed / degraded，并单独报告 L4 是否通过。
- L4 Playwright UI E2E 不能替代 L5，但可以作为 L5 失败时的剩余可用证据。

当前执行记录：

- 2026-05-19 使用本地 `.env` 跑通真实 LLM / AgentScope / PostgreSQL / R2DBC checkpoint / Playwright 主链路。
- 本次验证不输出或提交 `.env`；测试数据通过 `testRunId` 隔离并按 `l5-chat-minimal%`、最近 30 分钟 `ui-%` 清理。
- 2026-05-19 补充验证真实 PostgreSQL / MyBatis-Plus Mapper / R2DBC checkpoint 链路；无 `.env` 时仍可回落到 deterministic runtime + 内存仓储做 L3/L4 回归。

## 7. 数据隔离

所有 E2E 数据必须带 `testRunId`：

```text
testUser
testAgent
testSession
testMessage
testRun
testTrace
```

清理只能按相同 `testRunId` 执行，不允许清理真实数据。

测试 fixture：

- 每次 E2E 生成唯一 `testRunId`。
- 测试用户、默认 Agent、Provider / Model、Capability seed 优先通过公开 API 或测试 fixture 幂等创建；POC-1/POC-2 尚无 API 时可使用 Flyway seed 或测试初始化脚本。
- `TASK-V3-022 biz-chat 主流程` 负责判断公开 API 是否足以创建 E2E fixture；公开 API 不足时，由 `TASK-V3-023 stream persistence` 或对应 repo 任务提供 Flyway seed / 测试初始化脚本，并在测试报告中记录。
- 关键业务表优先使用显式 `test_run_id` 列；`metadata.testRunId` 只作为补充追踪。
- Playwright 请求应通过 fixture 注入 `Authorization` 和 `X-Test-Run-Id`。
- 清理失败必须在测试报告中记录影响范围，不能吞掉。
