
Agent 查询约束：

- `GET /api/agents/tags` 返回当前用户可见 Agent 的维度化标签分组。
- `GET /api/agents` 支持按单个 `tagGroup + tagCode` 过滤，例如 `tagGroup=domain&tagCode=contract`。
- 标签只用于 Agent 检索和展示，不替代用户授权、Capability gate 或运行时风险判定。
- 本工程不实现标签后台管理、标签推荐算法或多标签复杂组合查询。

Chat send 约束：

- `POST /api/chat/send` 当前只接收文本 `message`。
- `POST /api/chat/send` 成功时采用 send / stream 两步模型，返回 `201` 和最小响应体 `{ sessionId, runId, userMessageId, assistantMessageId }`；客户端随后通过 `GET /api/chat/{runId}/stream` 接收 SSE。
- `POST /api/chat/send` 不直接升级为 SSE 连接，避免与恢复、取消、执行详情查询和 checkpoint 语义耦合。
- 全局 `attachments` 字段在本工程中必须为空数组或省略；独立图片、包含图片的上传文件、文件内嵌图片抽取、OCR 预处理和派生上下文不进入当前实现。
- 如果客户端提交非空 `attachments`，本工程可返回 `VALIDATION_FAILED`，不冻结附件专用错误码。

- `agent_message` 至少包含 `message_id`、`session_id`、`user_id`、`agent_id`、`agent_version_id`、`role`、`content`、`status`、`run_id`、`test_run_id`、`created_at`。
- `agent_message_checkpoint` 至少包含 `checkpoint_id`、`run_id`、`message_id`、`event_id`、`sequence`、`event_type`、`payload_json`、`accumulated_content`、`created_at`、`metadata`。
- `agent_run` 至少包含 `run_id`、`session_id`、`user_id`、`agent_id`、`agent_version_id`、`status`、`trace_id`、`started_at`、`completed_at`、`error_code`、`test_run_id`。
- `agent_span` 至少包含 `span_id`、`run_id`、`parent_span_id`、`span_type`、`name`、`status`、`started_at`、`ended_at`、`error_code`。
- `agent_tool_call` 至少包含 `tool_call_id`、`run_id`、`span_id`、`tool_name`、`status`、`input_summary`、`output_summary`、`error_code`。
- `agent_audit_log` 至少包含 `audit_id`、`user_id`、`action`、`resource_type`、`resource_id`、`risk_level`、`result`、`trace_id`、`run_id`、`span_id`、`summary`、`created_at`、`metadata`。

状态枚举最低语义：

- `agent_session.status` 至少包含 `active`、`archived`、`deleted`。是否存在 running run 不由 session status 表达，而由 `agent_run.status` 和同 session 运行互斥约束判定。
- `agent_message.status` 至少包含 `created`、`streaming`、`completed`、`failed`、`cancelled`。
- `agent_run.status` 至少包含 `queued`、`running`、`completed`、`failed`、`cancelled`、`timeout`。

checkpoint 语义：

- `event_id` 对应平台 SSE envelope 的 `eventId`，用于 `Last-Event-ID` 恢复和客户端去重。
- `payload_json` 保存该 `event_type` 对应的 SSE envelope `payload`，不保存未脱敏 runtime raw。
- `accumulated_content` 保存当前 assistant 最终正文的累计快照，不是本次 delta；thinking 不混入该字段。
- checkpoint 写入必须按 `run_id + sequence` 幂等。

`agent_message.content` 与 checkpoint 关系：

- `role=user` 的 `agent_message.content` 保存用户提交的最终文本。
- `role=assistant` 的 `agent_message.content` 保存 final flush 后的最终完整正文。
- run 进行中，assistant 增量正文以 `agent_message_checkpoint.accumulated_content` 为准；可选更新 `agent_message.content` 用于恢复展示，但不得以该字段替代 checkpoint 作为恢复依据。
- run 完成、失败或取消时，final flush 必须把最后一次有效 `accumulated_content` 回写到 assistant message，并同步 message / run 终态。

工具消息展示边界：

- `role=tool` 的 `agent_message` 可以保存工具执行详情或结果摘要，用于审计、回放和执行详情。
- Chat 主时间线默认展示 `tool.call.*` SSE 摘要，不把 `role=tool` 消息渲染成普通对话气泡。
- 原始工具参数、MCP 请求、Skill 输入和外部响应只进入 Run/Span/Audit 的受控字段，普通用户不可见。

## 7. 初始化与最小治理

Provider / Model：

- POC-1/POC-2 必须通过 Flyway seed、本地初始化脚本或测试 fixture 创建最小 Provider / Model 元数据。当前 POC-2 已通过 Flyway seed 创建默认 Agent、标签和 `chat.basic` Capability；Provider / Model 运行参数由环境变量和本地 fixture 装配，不在数据库迁移中写入密钥或真实 provider 凭据。
- 密钥只保存环境变量引用名或 secret ref，例如 `HTAM_LLM_API_KEY_REF`，不得把明文 key 写入数据库迁移、文档、日志或测试报告。
- 默认 Agent 必须引用已启用的 provider / model；provider 不可用时返回 `RUNTIME_UNAVAILABLE`。

IAM seed：

- POC-1/POC-2 必须通过 Flyway seed、本地初始化脚本或测试 fixture 创建最小 `sys_user`、`sys_role`、`sys_user_role` 数据；当前 POC-2 使用 Bearer token 解析出的本地 `UserContext` 作为测试 fixture。
- 如实现权限码校验，必须同步创建最小 `sys_permission` 和 `sys_role_permission`。
- POC 阶段可使用内置测试用户或本地 mock user，但仍必须写入可追踪的 `user_id`，不得使用空用户绕过授权。

Agent Version：

- `chat-minimal` 至少创建一个初始 `agent_version` 记录。
- Chat send 生成的 message / run 必须能追溯本次使用的 `agent_id` 和 `agent_version_id`。
- Agent 配置发生发布级变化时新增版本，不直接覆盖已被历史 run 引用的版本语义。

Capability seed：

- 至少创建一个 enabled、审核通过、风险等级为 `low` 的普通 Chat capability，例如 `chat.basic`。
- 默认 Agent 必须绑定该 capability。
- 当前用户或测试用户必须具备该 capability 的使用权限。
- 未审核、未授权、禁用或非 `low` 风险 capability 不得进入 `runtime-agentscope`。

最小 Capability Gate：

- 只允许 enabled、审核通过、绑定到当前 Agent、当前用户有权使用、风险等级为 `low` 的普通 Chat capability 进入 `runtime-agentscope`。
- 未授权、未审核、已禁用或风险等级超过 `low` 时返回对应错误码，不隐式降级。
- OCR、附件解析、Shell、Python、Browser 自动化、文件写入、系统命令不进入当前 `chat-minimal` 实现。

## 8. Chat 与 SSE 行为补充

Session 并发：

- 同一 `sessionId` 同时只允许一个 running run。
- 已存在 running run 时，新的 `POST /api/chat/send` 返回 `SESSION_BUSY`，不隐式取消旧 run。
- `cancel` 只取消指定 `runId`，不得取消同一用户的其他 session。

SSE 连接与恢复：

- `GET /api/chat/{runId}/stream` 建立后，应发送可恢复的首个运行态事件，例如 `run.started` 或最近 checkpoint 后的下一条事件。
- `sequence` 在同一 run 内单调递增。
- 客户端重新请求 `GET /api/chat/{runId}/stream` 并携带 `Last-Event-ID` 后，服务端按 `runId + eventId` 定位 checkpoint，回放该事件之后已持久化事件。
- 如果 run 已完成、失败或取消，服务端回放剩余终态事件后关闭连接。
- 无法定位 checkpoint、事件不属于该 run 或已过期时返回 `STREAM_RESUME_FAILED`。
- 默认 15 秒无业务事件时发送 `heartbeat`；客户端 30 秒无任何事件可判定疑似断线并恢复。
- `heartbeat` 只用于保活，不改变 run / message 状态。

重新生成与编辑重发：

- `regenerate` 基于被选中的历史消息创建新 run，不修改原消息正文。
- `edit-resend` 基于用户编辑后的消息创建新 run，必须保留原消息和编辑后的消息关联关系。
- 两者都必须进入同一套权限、Capability Gate、Run/Span、SSE 和审计链路。

thinking 内容：

- POC 阶段允许通过 `assistant.thinking.delta` / `assistant.thinking.done` 流式展示。
- thinking 不混写进最终 assistant 正文。
- 默认只作为 stream checkpoint / Run 观测数据保留；是否长期落入 `agent_message` 独立字段后续再冻结。

## 9. 最小身份与测试隔离

身份方案：

- POC 阶段使用 `Authorization: Bearer <test-token>` 或等价本地 mock token 生成 `UserContext`。
- SSE 连接必须携带同一身份。前端使用 `fetch` stream 建立 SSE，以便设置 `Authorization`、`Last-Event-ID` 和取消控制。
- 当前工程不实现完整登录、刷新 token、OAuth、SSO 或管理端用户配置。

testRunId：

- API/SSE E2E 和 Playwright UI E2E 必须生成唯一 `testRunId`。
- `testRunId` 可以通过 `X-Test-Run-Id` header、请求 `metadata.testRunId` 或测试 fixture 写入，但落库优先使用显式 `test_run_id` 列。
- 清理只能按相同 `testRunId` 删除测试数据，不允许按名称模糊清理。
