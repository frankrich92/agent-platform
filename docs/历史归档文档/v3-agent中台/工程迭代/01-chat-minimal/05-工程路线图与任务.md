# chat-minimal 工程路线图与任务

## 1. 定位

`chat-minimal` 是 `EPIC-V3-A` 的独立小工程。它只负责把业务老师可用的最小 Chat 闭环跑通，并为后续 Admin、任务中心、工作流、外部复杂 Agent 和 input-ocr 提供可复用的契约基线。

全局小工程拆分和跨工程门禁见：

```text
docs/v3-agent中台/08-小工程切片与验收门禁.md
```

本文件只维护 `chat-minimal` 内部路线图，不承载后续小工程的详细 Backlog。

## 2. 阶段切片

| 阶段 | 目标 | 范围 | 验收等级 | 状态 |
| --- | --- | --- | --- | --- |
| POC-0 | 文档结构、全局基线和本工程契约切片进入 Review | 顶层索引、全局契约基线、`chat-minimal` 工程目录、任务包迁移 | L0 | Review |
| POC-1 | 后端模块骨架和公共 Java 契约可编译 | Maven 多模块、`agent-domain`、`agent-api`、`runtime-spi`、`repo-spi`、architecture test | L2 | Review |
| POC-2 | Chat 主链路和最小前端闭环 | Agent 库、标签筛选、Session、Chat、SSE、Run/Span、checkpoint、Playwright UI E2E、AgentScope runtime 适配 | L5 passed | Review |
| 横切 | 测试、真实 E2E、AGENTS、CI | Playwright、e2e-real、分层规则、质量门禁 | L4-L5 | Pending |

## 3. 任务包目录

本工程所有任务过程文档放在：

```text
docs/v3-agent中台/工程迭代/01-chat-minimal/ai-tasks/
```

任务目录至少包含：

```text
task.md
test-report.md
handoff.md
```

涉及 API、SSE、RuntimeEvent、错误码或公共 Java SPI 的任务，还必须包含：

```text
contract-notes.md
```

涉及 DTO、数据模型、表结构或状态机的任务，也必须写入 `contract-notes.md`。其中必须包含具体参考依据：参考项目、版本/commit、源码路径或官方 endpoint、实际 API / 类 / 方法 / 事件 / 字段、采纳点、不采纳点和原因。只写“参考 AgentScope / 历史实现 / V3 主契约”不允许进入 Review。

共享模板来自：

```text
docs/v3-agent中台/templates/
```

POC-2 任务包已创建并进入 Review。真实 LLM / AgentScope / PostgreSQL / R2DBC checkpoint 链路已使用本地 `.env` 补测通过；`.env` 不入库、不进入报告。


POC-2 可以按多 Agent 并行范式创建任务包，但仍共同服务 `chat-minimal` 同一个可运行闭环。当前任务包按下表拆分：

| 子 Agent | 建议任务 | owned modules / files | 主要验收 |
| --- | --- | --- | --- |
| runtime-agent | `TASK-V3-020` | `agent-runtimes/runtime-agentscope`、必要的 runtime 测试 | AgentScope Java 适配、deterministic fallback 和 RuntimeEvent 输出 |
| capability-agent | `TASK-V3-021` | `agent-platform/platform-capability`、`biz-chat` 中 capability 查询接入 | Agent / Capability 未授权或未审核时可拒绝 |
| biz-agent | `TASK-V3-022` | `agent-biz/biz-chat`、`biz-session`、`biz-agent`、`biz-execution`、`agent-boot` | Chat 主流程、Session、Run 状态流转、执行详情查询 |
| stream-repo-agent | `TASK-V3-023` | `platform-stream`、`repo-spi`、`repo-mybatis`、`repo-r2dbc-stream` | SSE checkpoint 语义、Last-Event-ID、final flush |
| frontend-agent | `TASK-V3-024` | `source/v3-agent-platform-ui` | Chat 页面、Agent 选择、SSE 增量展示、Playwright |
| e2e-agent | `TASK-V3-900` / `TASK-V3-901` | API/SSE E2E、Playwright、`e2e-real` | testRunId 隔离、真实链路验收 |
| review-agent | POC-2 Review | 任务报告、交接记录、owned files 检查 | 不越权、不破坏契约、验证证据完整 |

并行前必须由主 Agent 或 review-agent 复核并冻结 `02-工程契约切片.md`、`03-工程技术设计.md`、POC-2 子 Agent 分工表和 POC-2 任务单；公共 DTO、SPI、SSE envelope、错误码和 Flyway 迁移必须指定唯一 owner。

POC-2 完成条件：

- 普通 Chat 通过 `runtime-agentscope` 适配 `agentscope-java` 的 `ReActAgent`；无 `.env` 时可用 deterministic runtime 做本地验收。
- Chat SSE envelope、RuntimeEvent、Run/Span、Message、checkpoint 能相互追踪。
- `Last-Event-ID` 恢复、取消、失败、final flush 有 API/SSE E2E 覆盖。
- Chat 页面通过 Playwright UI E2E。
- 具备 `.env` 时，`e2e-real` 能跑通真实 LLM / AgentScope / PostgreSQL / R2DBC checkpoint 链路。
- 当前 POC-2 的普通 CRUD 和历史读取已由 `repo-mybatis` 使用 MyBatis-Plus Mapper 接入 PostgreSQL；R2DBC checkpoint 已覆盖 `Last-Event-ID` 恢复，后续 hardening 只保留多节点恢复和 `repo-r2dbc-stream` 独立 adapter 拆分。
- 图片型输入、文件内嵌图片抽取、OCR 预处理和 `input.ocr.*` 事件不属于 POC-2 完成条件，后续作为 `input-ocr` 小工程独立创建任务包。

## 8. 契约合并规则

- `02-工程契约切片.md` 是本工程当前冻结范围。
- 任务内局部契约先写入任务目录的 `contract-notes.md`。
- `contract-notes.md` 必须区分 HTTP API / SSE event / RuntimeEvent / 错误码 / DTO / 数据模型 / 表结构 / 状态机是否受影响，并写明实际参考的开源 API 或模型。
- 只有跨任务稳定、需要长期复用的契约，才合并回全局基线文档。
- 字段删除、重命名、事件语义变化、执行底座取舍等破坏性调整，必须在本工程 `adr/` 下新增 ADR。

## 9. 阶段切换规则

- POC-0 未人工确认前，不进入真实代码开发。
- POC-1 公共契约未冻结前，不启动多子 Agent 并行写代码。
- POC-2 未达到 L5 前，不启动 Admin 完整治理、任务中心、工作流、外部复杂 Agent 或 input-ocr 小工程；当前 `chat-minimal` L5 已通过，可进入人工评估是否启动后续小工程。
- 如果 `.env` 存在但真实 LLM / AgentScope / PostgreSQL 链路失败，只能标记为 L5 failed / degraded；是否启动后续小工程必须由人工在交接记录中显式确认，不能用 L4 结果自动替代 L5。
- Playwright UI E2E 缺失时，不认为 Chat 体验完成。
