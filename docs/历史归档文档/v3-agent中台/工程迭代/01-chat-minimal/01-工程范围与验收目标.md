# 工程范围与验收目标

## 1. 工程定位

`chat-minimal` 是 V3 的第一个可运行小工程。它只验证 V3 Agent 中台最小闭环：业务老师选择被授权 Agent，创建会话，发送消息，看到真实流式回复，并能查询执行记录。

它不是完整 V3 产品，不承担 Admin、任务中心、工作流和外部复杂 Agent 的交付。

## 2. 用户目标

业务老师：

- 能看到一个被授权 Agent。
- 能看到可用于筛选 Agent 的基础标签。
- 能创建和继续一个会话。
- 能发送、停止、重新生成、编辑重发消息。
- 能看到流式输出和最终回复。
- 能查看一次执行的基本状态、错误和 traceId。

平台开发者：

- 能通过 Run / Span / SSE checkpoint 排查 Chat 主链路。
- 能用 `testRunId` 隔离和清理 E2E 数据。

## 3. 范围

包含：

- Agent 列表、详情和标签分组的用户侧查询。
- Agent 列表按单个标签过滤。
- Agent 标签只用于检索和展示，不替代用户授权、Capability gate 或运行时风险判定；详细契约见 `02-工程契约切片.md`。
- Session 创建、列表、详情、重命名、删除。
- Chat send / cancel / regenerate / edit-resend。
- Chat SSE stream。
- 最小用户身份和 Agent 授权校验。
- RuntimeCapabilityPlan 最小 gate。
- `runtime-agentscope` 适配 AgentScope Java。
- MyBatis 普通 CRUD。
- R2DBC stream checkpoint / final flush。
- Chat 页面、会话列表、Agent 选择和执行详情最小入口。

不包含：

- Admin 完整配置后台。
- 任务中心。
- 工作流。
- 外部复杂 Agent。
- 高风险 Shell / Python / Browser 沙箱真实执行。
- 图片型输入、文件内嵌图片抽取、OCR 预处理和派生上下文展示。
- 多租户组织树。
- RAG / 向量检索。
- 标签后台管理和多标签复杂组合查询。

## 4. 验收等级

目标验收：L5。

阶段门禁：

- L1：公共 Java 契约、DTO / SPI、状态枚举和值对象单元测试通过。
- L2：模块骨架、architecture test、MyBatis / R2DBC / Capability gate stub 模块集成测试通过。
- L3：Chat API/SSE E2E 通过，覆盖发送、取消、失败、恢复和错误码。
- L4：Playwright UI E2E 通过，覆盖真实页面操作和执行详情查看；具体场景见 `04-工程测试策略与真实E2E.md` 第 5 节。
- L5：具备 `.env` 时跑通真实 LLM + AgentScope Java + PostgreSQL + SSE + 前端页面。

## 5. 人工评审口径

人工只需要判断：

- `chat-minimal` 范围是否足够小。
- 契约切片是否能支撑第一个真实 Chat 闭环。
- API、SSE、Runtime SPI、DTO、数据模型和状态枚举是否已经标注具体参考来源，包括项目、版本/commit、源码路径或官方 endpoint、实际接口/字段、采纳点和不采纳点。
- 验收命令是否能证明该小工程完成。
- 暂缓范围是否清晰，不会偷偷滑向完整 V3。
