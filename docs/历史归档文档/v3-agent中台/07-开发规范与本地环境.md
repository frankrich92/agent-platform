# 开发规范与本地环境

## 1. 基础规范

后端：

- Java 21。
- Spring Boot 4.0.6。
- Maven 4.x RC 多模块。
- 包名使用 `com.htam...`。
- 4 空格缩进。
- 优先使用明确领域命名，例如 `AgentSession`、`AgentMessage`、`LlmProviderAdapter`、`ContextAssembler`。

前端：

- Vue 3。
- TypeScript。
- Pinia。
- Vite。
- Vue Router 4。
- Element Plus。
- API client 使用 fetch wrapper。
- SSE client 使用 `fetch` + `ReadableStream` + `AbortController`，不默认使用原生 `EventSource`；需要自定义 `Authorization`、`Last-Event-ID` 和取消控制。
- 组件、store、api、types 分层。
- 页面避免巨型单文件实现。

文档：

- 面向贡献者的说明优先中文。
- API 名称、协议名、代码符号保持英文。

## 2. Java 规范参考

可参考：

- Google Java Style Guide。

- Spring Boot 官方最佳实践。
- Effective Java。
- Clean Architecture / Hexagonal Architecture。

项目约束优先级高于通用规范。

## 3. 前端规范参考

可参考：

- Vue 官方 Style Guide。
- TypeScript Handbook。
- Pinia 官方文档。
- Playwright Best Practices。

页面实现应以业务工作流为中心，不做装饰性 landing page。

## 4. 模块规范

V3 代码开发根目录：

```text
source/v3-agent-platform
source/v3-agent-platform-ui
```

约束：

- 新的后端重构代码默认写入 `source/v3-agent-platform`。
- 新的前端重构代码默认写入 `source/v3-agent-platform-ui`。
- 旧 `source/htam-agent-platform` 和 `source/htam-agent-platform-ui` 仅作为历史实现参考或迁移来源。
- AI agent 不应在旧目录和 V3 目录之间同时开发同一功能，除非任务单明确要求迁移。
- `agent-domain` 不依赖基础设施。
- `agent-api` 不放业务逻辑。
- `agent-biz` 不直接访问 Mapper、R2DBC Client、AgentScope 实现类。
- `agent-admin` 管配置，不做运行时决策。
- `agent-platform` 不反向依赖 biz/admin。
- `agent-runtimes` 不访问数据库。
- `agent-repo` 不包含业务流程。
- `agent-boot` 不写核心业务逻辑。

## 5. 持久化规范

- 普通 CRUD 使用 MyBatis-Plus。
- SSE checkpoint / final flush 使用 R2DBC。
- 不使用手写 Spring JDBC / JdbcClient 作为新架构方案。
- 已应用 Flyway 迁移不改语义。
- 新结构调整必须新增迁移。

## 6. 安全规范

- 不提交密钥。
- `.env` 只保存在本地。
- `application.yml` 只能引用环境变量。
- 日志、测试、文档、PR 描述不输出 API key、token、数据库密码。
- 普通用户页面不展示敏感工具参数。

## 7. Agent 能力开发规范

必须优先复用 `agentscope-java`：

- ReActAgent。
- Toolkit。
- SkillBox。
- MCP tool。
- Memory。
- Session。
- StreamOptions。
- 事件体系。

平台职责限定为：

- 用户管理。
- Agent 授权。
- 用户隔离。
- 输入预处理治理。
- 记忆数据治理。
- 能力配置。
- 审计观测。
- Run/Span 记录。
- SSE 协议适配。
- 前端体验。

OCR、文档解析、表格解析等输入预处理能力必须作为受控 capability 进入 Capability gate。前端或业务服务不允许绕过平台直接调用 OCR provider，也不允许把图片原件或文件内嵌图片透传给非多模态主模型。

新增 Agent/MCP/Skills/Tool / input-preprocessor 前，必须先检查 AgentScope、现有平台能力或调研结论是否已有能力。

## 8. 本地工具链

macOS 参考：

```bash
export JAVA_HOME=~/.sdkman/candidates/java/21.0.11-tem
export MAVEN_HOME=~/.sdkman/candidates/maven/4.0.0-rc-5
export NODE_HOME=~/.nvm/versions/node/v24.15.0
export PYTHON_HOME=/Volumes/ppj/miniforge3/envs/agent
export PATH="$JAVA_HOME/bin:$MAVEN_HOME/bin:$NODE_HOME/bin:$PATH"
conda activate agent
```

WSL2 参考：

```bash
export JAVA_HOME=/opt/jdk-21.0.7
export MAVEN_HOME=/opt/apache-maven-4.0.0-rc-5
export NODE_HOME=/root/.nvm/versions/node/v24.15.0
export PYTHON_HOME=/app/miniforge3/envs/agent
export PATH="$JAVA_HOME/bin:$MAVEN_HOME/bin:$NODE_HOME/bin:$PATH"
conda activate agent
```

版本约束：

- V3 后端基线固定为 JDK 21、Spring Boot 4.0.6、Maven 4.x RC。
- Node.js 推荐 v24.15.0；临时环境最低不得低于 v24.13.0。
- macOS 和 WSL2 可以使用不同安装路径，但 `java -version`、`mvn -version`、`node -v` 和 Spring Boot 父版本必须落在上述基线。
- 如需切换 Spring Boot 或 Maven 主版本，必须先补充兼容性验证和 ADR。

非交互 shell 中无法 activate 时：

```bash
$PYTHON_HOME/bin/python source/test/test_chat_e2e.py
```

## 9. 本地依赖搭建

POC 阶段默认依赖 PostgreSQL 16+。本地可使用已有 PostgreSQL，也可由后续任务单提供 Docker Compose 或 Testcontainers。

推荐最小数据库变量名：

```text
HTAM_DB_HOST
HTAM_DB_PORT
HTAM_DB_NAME
HTAM_DB_USERNAME
HTAM_DB_PASSWORD
HTAM_LLM_PROVIDER
HTAM_LLM_BASE_URL
HTAM_LLM_API_KEY_REF
HTAM_LLM_MODEL
HTAM_TEST_AUTH_TOKEN
```

约束：

- `.env.example` 只允许写变量名和示例占位，不写真实密钥。
- `application.yml` 只引用环境变量，不写明文密码和 token。
- Testcontainers 建议使用 `postgres:16-alpine` 作为默认镜像；如切换 PostgreSQL 主版本，任务报告必须说明原因。
- Flyway 默认 schema、初始化用户、默认 Agent、Provider / Model、Capability seed 由小工程 contract slice 或任务单冻结。
- 本地端口、CORS、前后端启动顺序由 POC-2 任务包补充，不在全局文档中硬编码。

## 10. 推荐命令

后端：

```bash
cd source/v3-agent-platform
mvn test
mvn verify
```

前端：

```bash
cd source/v3-agent-platform-ui
npm install
npm run lint
npm run typecheck
npm run test
npm run build
npm run e2e
```

当前模块尚未创建时，以任务单指定命令为准。

## 11. 提交规范

使用 Conventional Commit：

```text
docs: update v3 platform docs
feat: add session api
fix: release session lock on stream cancel
test: add chat e2e
```

PR 必须包含：

- 变更摘要。
- 影响模块。
- 验证命令。
- 风险。
- UI 变更截图或 Playwright 产物。
- 是否触碰公共契约。
