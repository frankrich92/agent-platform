# ADR-0001 决策记录模板

## 状态

```text
Proposed / Accepted / Superseded / Rejected
```

## 日期

```text
YYYY-MM-DD
```

## 背景

描述为什么需要做这个决策：

- 当前问题。
- 业务约束。
- 技术约束。
- 已有方案不足。

## 决策

明确最终选择：

```text
我们决定……
```

## 备选方案

列出曾考虑的方案：

```text
方案 A：
方案 B：
方案 C：
```

## 取舍分析

从以下角度分析：

- 复杂度。
- 可维护性。
- 可测试性。
- 安全性。
- 性能。
- AI Native 并行开发影响。

## 影响范围

```text
影响模块：
影响接口：
影响数据：
影响测试：
影响文档：
```

## 迁移策略

说明如何从旧方案迁移到新方案：

- 是否需要数据迁移。
- 是否需要兼容旧接口。
- 是否需要灰度。
- 是否需要回滚方案。
- 降级或回退触发条件。

## 验收方式

```text
验收等级：
验证命令：
E2E 场景：
人工评审点：
```

## 后续事项

```text
后续事项：
风险：
待确认：
```

## 编号规则

```text
ADR-0001-模板.md
ADR-0002-持久化策略.md
ADR-0003-AgentScope默认执行底座.md
```

规则：

- 一个 ADR 只记录一个重大决策。
- 已 Accepted 的 ADR 不直接改语义；需要新 ADR supersede。
- 架构、数据、契约、安全、运行时重大变更必须有 ADR。
