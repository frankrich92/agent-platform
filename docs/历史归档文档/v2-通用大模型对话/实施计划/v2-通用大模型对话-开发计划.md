# 通用大模型对话 V2 开发计划

> 注意：本文档为历史阶段文档，仅作为需求、调研和演进参考。
> 当前 Agent 中台架构与后续开发以 `docs/v3-agent中台/` 为准。
> AI agent 执行开发任务前必须先阅读 `docs/README.md` 和 V3 架构文档。

> 版本：v2
> 日期：2026-05-15
> 依据文档：`01-通用大模型对话V2需求.md`、`02-通用大模型对话V2技术方案.md`、`03-通用大模型对话V2详细设计.md`
> 目标：把“带用户管理的 OpenClaw + Hermes Agent”式通用 Agent 对话平台 V2 拆解为可执行开发任务，覆盖 P0、P1、P2 能力。

## 1. V2 范围锁定

V2 纳入：

- 平台内部用户模型，当前由 `X-App-Code` 映射 `userCode`。
- Agent 定义、Agent 授权、Agent 列表和默认通用 Agent。
- 会话、消息、记忆、Run/Span 按 `userCode + agentId` 隔离。
- MCP server、Skills 和内置工具统一能力注册与 Agent 白名单。
- 用户可查看和清空自己在某个 Agent 下的文本型记忆。
- 真正上游流式。
- 前端流式消息 ID 回写。
- 代码高亮、Markdown 表格、重新生成、编辑重发、会话重命名、搜索、收藏、复制、导出、主题、快捷键。
- 会话和消息分页。
- 上下文长度保护。
- 多 Provider 和模型切换。
- Run/Span、token usage、耗时、错误和运行详情。
- `AgentRuntime`、`OpenAiChatRuntime`、`AgentScopeReActRuntime`、受控 MCP/Skills 注册和工具调用事件。
- 前端组件化重构和 Pinia。
- 开发者调试视图。

V2 不纳入：

- 企业级账号体系、复杂 RBAC、SSO/OIDC、LDAP、用户组同步。
- 文件上传、多模态、语音。
- RAG、向量库、跨用户共享知识库。
- 自动记忆提炼、梦境系统、后台学习闭环和技能自创建。
- 分支对话完整树模型和 Artifacts。
- 移动端、WebSocket、多渠道接入。
- AgentScope Studio 生产页面嵌入。

## 2. 总体里程碑

1. **M1 平台域模型**：用户、Agent、授权、能力、记忆和首次上线 baseline。
2. **M2 P0 主链路修复**：真正流式、JSON envelope SSE、ID 回写、Run 优先、上下文保护。
3. **M3 P1 体验增强**：搜索、分页、主题、快捷键、导出、Markdown 增强、运行详情基础字段。
4. **M4 前端架构升级**：Agent 选择、组件化拆分、Pinia、API 层重组。
5. **M5 多 Provider 与模型切换**：Provider 配置、模型列表、Agent 默认模型和会话级模型选择。
6. **M6 AgentRuntime、MCP 与 Skills**：ReAct runtime、MCP/Skills registry、工具事件映射、安全边界。
7. **M7 Run/Span 与开发者调试**：完整运行链路、工具调用可视化、调试视图。
8. **M8 联调验收**：真实 LLM、受控 MCP/Skills、用户隔离、并发、取消、失败态和敏感信息检查。

## 3. M1 平台域模型

### BE-01 用户、Agent 与授权表

目标：

- 建立 `agent_user`、`agent_definition`、`agent_user_grant`。
- 初始化一个默认“通用 Agent”，并授权给当前测试用户或默认 `appCode`。

验收标准：

- `X-App-Code` 可映射或创建 `agent_user`。
- 当前用户只能查询授权给自己的 active Agent。
- 未授权 Agent 创建会话、发送消息、查看详情均失败。

### BE-02 能力与记忆表

目标：

- 建立 `agent_capability`、`agent_definition_capability`、`agent_memory`。

验收标准：

- MCP、skill、builtin tool 统一保存为 capability。
- Agent 只能引用 active capability。
- `agent_memory` 按 `user_code + agent_id` 隔离。

### BE-03 Agent 基础接口

接口：

- `GET /api/agent/agents`
- `GET /api/agent/agents/{agentId}`
- `GET /api/agent/agents/{agentId}/capabilities`
- `GET /api/agent/agents/{agentId}/memories`
- `DELETE /api/agent/agents/{agentId}/memories`

验收标准：

- 只返回当前用户被授权 Agent。
- 能力摘要不返回密钥和敏感配置。
- 用户只能查看和清空自己在该 Agent 下的记忆。

### BE-04 首次上线 baseline

目标：

- 项目未上线前重整 Flyway baseline，形成面向 V2 首次上线的一组清晰初始化脚本。

验收标准：

- 初始化脚本包含用户、Agent、授权、能力、记忆、会话、消息、Run/Span。
- 不再以兼容旧数组响应和旧 schema 为目标添加兼容迁移。

## 4. M2 P0 主链路修复

### BE-05 真正流式改造

目标：

- 改造 `OpenAiCompatibleAdapter`，禁止使用完整响应体聚合模拟流式。

涉及范围：

- `agent-core/llm/OpenAiCompatibleAdapter.java`
- `OpenAiCompatibleAdapterTest`

验收标准：

- 慢速上游每输出一条 `data:`，底层 provider 能按片段收到 `LlmProviderEvent`。
- 上游 `[DONE]` 能发出 `provider_completed`，并由 runtime 转成 `run_completed`。
- 上游非 2xx、连接中断、JSON 解析失败能转为错误。
- 客户端取消时输入流关闭，不泄漏会话锁。

测试点：

- 使用本地 stub HTTP server 模拟慢速 SSE。
- 单元测试断言首个事件在上游完整结束前到达。

### BE-06 JSON envelope SSE 与 ID 回写

目标：

- 后端 SSE 统一输出 JSON envelope。
- 前端收到 `run_started` 后用后端 ID 替换本地临时 ID。

验收标准：

- 所有 SSE `data` 都是 JSON。
- 事件包含 `eventId/runId/sessionId/messageId/sequence/createdAt`。
- parts 追加、锚点定位、消息操作都使用后端 ID。
- 流完成后刷新恢复无重复消息。

### BE-07 Run 优先与 Agent 授权主链路

目标：

- 普通发送、重新生成、编辑重发先创建 Run，再关联消息。
- 所有主链路操作校验 `userCode + agentId` 授权。

验收标准：

- 未授权 Agent 不能创建会话或发送消息。
- 同一 Agent 授权给多个用户时，会话、消息、Run 互相不可见。
- `run_completed/run_failed/cancelled` 状态完整。

### BE-08 上下文预算与用户记忆注入

目标：

- 为 `ContextAssembler` 增加 token 粗估、历史裁剪和当前用户当前 Agent 记忆注入。

验收标准：

- 系统提示词、当前用户消息和必要记忆优先保留。
- thinking 不进入上下文。
- 历史过长时裁剪早期消息并记录裁剪数量。
- 只注入当前 `userCode + agentId` 的 active 记忆。
- 当前用户消息超长返回 `CONTENT_TOO_LONG` 或等价错误。

### BE-09 基础消息操作

目标：

- 会话重命名、助手重新生成、用户消息编辑重发。

接口：

- `PATCH /api/agent/sessions/{sessionId}`
- `POST /api/agent/sessions/{sessionId}/messages/{assistantMessageId}/regenerate`
- `POST /api/agent/sessions/{sessionId}/messages/{userMessageId}/edit-and-resend`

验收标准：

- 使用同一用户消息和目标位置前的上下文重新生成。
- 返回 `run_started/thinking_delta/message_delta/run_completed/error`。
- 旧助手消息保留审计，普通展示使用新版本。
- 同会话生成中返回 `SESSION_BUSY`。
- 不覆盖原消息，创建新用户消息版本。
- 后续替换消息在普通展示中隐藏。

### FE-02 基础消息操作

目标：

- 增加复制、重新生成、编辑重发、详情入口占位。

验收标准：

- 生成中冲突操作禁用。
- 操作失败展示错误。
- 重新生成和编辑重发能接入 SSE。

### FE-03 Markdown 与代码高亮

目标：

- 支持 Markdown 表格和代码语法高亮。

验收标准：

- 代码块可复制。
- HTML 输出经过安全处理。
- thinking 和最终回复渲染一致。

## 5. M3 P1 体验增强

### BE-06 会话搜索、收藏、复制、导出

接口：

- `GET /api/agent/sessions?pageSize=&cursor=&keyword=&favorite=`
- `PATCH /api/agent/sessions/{sessionId}`
- `POST /api/agent/sessions/{sessionId}/duplicate`
- `GET /api/agent/sessions/{sessionId}/export?format=markdown|text`

验收标准：

- 所有接口按 `userCode + agentId` 隔离。
- 搜索只查 active 会话标题。
- 复制不复制 streaming 消息。
- 导出不包含敏感信息。

### BE-07 会话和消息分页

目标：

- 会话列表和消息列表改为游标分页。

验收标准：

- 返回 `{items,nextCursor,hasMore}`。
- 消息分页顺序稳定。
- 前端可继续加载更早消息。

- 分页响应是首次上线正式契约，不保留旧数组响应接口。

### BE-08 Run 基础记录

目标：

- 新增 `agent_run`，记录每次生成的模型、状态、耗时、token 和错误。

验收标准：

- 普通发送、重新生成、编辑重发都创建 Run。
- `run_completed` 时更新 token 和耗时。
- `error/cancel` 时更新失败或取消状态。

### FE-04 会话组织增强

目标：

- 支持搜索、收藏、重命名、复制、导出和分页加载。

验收标准：

- `Ctrl/Command+K` 聚焦搜索。
- 收藏会话可筛选。
- 导出触发浏览器下载。

### FE-05 主题与快捷键

目标：

- 支持浅色、深色、跟随系统。
- 支持常用快捷键。

验收标准：

- 偏好保存在本地。
- 输入框内快捷键不破坏换行和输入法。

### FE-06 运行详情抽屉基础版

目标：

- 展示 Run 的模型、状态、token、耗时、错误摘要。

验收标准：

- 助手消息可打开详情。
- 错误消息可查看详情。
- 普通用户不展示敏感 metadata。

## 6. M4 前端架构升级

### FE-07 引入 Pinia

目标：

- 新增 store 管理 auth、agent、session、message、stream、memory、preference。

验收标准：

- 原 `App.vue` 中核心状态迁移到 store。
- store 有单元测试。
- V1 原有交互不回退。

### FE-08 组件化拆分

目标：

- 拆分布局、Agent 选择、会话、消息、输入、记忆、运行详情、模型选择组件。

验收标准：

- `App.vue` 只保留应用壳和组合逻辑。
- 单个组件职责清晰。
- CSS 按组件或模块整理，避免继续膨胀单一样式文件。

### FE-09 API 层重组

目标：

- 将 `api.ts` 拆为 agents、memories、sessions、messages、providers、runs 等模块。

验收标准：

- 所有请求统一带认证头。
- SSE 读取封装为 `useSseStream`。
- 未知 SSE 事件可忽略。

## 7. M5 多 Provider 与模型切换

### BE-09 Provider 配置模型

目标：

- 支持多个 Provider 和模型。

验收标准：

- 配置绑定支持 `openai-compatible` 和 `agentscope-react`。
- 配置错误 fail closed。
- 默认 Provider/模型可用。

### BE-10 Provider/模型列表接口

接口：

- `GET /api/agent/providers`

验收标准：

- 不返回 API Key。
- 返回默认 Provider、默认模型、可选模型列表。

### BE-11 会话级模型选择

目标：

- Agent 可配置默认 provider/model，发送请求可指定 provider/model，会话可保存覆盖值。

验收标准：

- 新消息使用选定模型。
- 历史助手消息保留实际模型记录。
- 无效模型返回 `MODEL_NOT_AVAILABLE`。

### FE-10 模型选择 UI

目标：

- 增加模型选择控件。

验收标准：

- 展示当前模型。
- 用户可选择可用模型。
- 模型切换只影响后续消息。

## 8. M6 AgentRuntime、MCP 与 Skills

### BE-12 AgentRuntime 与 AgentScopeReActRuntime

目标：

- 新增 `AgentRuntime`、`OpenAiChatRuntime`、`AgentScopeReActRuntime`。

验收标准：

- 可通过配置选择 `agentscope-react`。
- 使用 `ReActAgent.stream` 返回统一 `AgentStreamEvent`。
- thinking/text/tool 事件映射正确。
- 不依赖 Agent 内存作为跨用户长期历史。
- 只注入当前 `userCode + agentId` 的用户记忆。

### BE-13 CapabilityRegistry、MCP 与 Skills 安全策略

目标：

- 统一管理 MCP server、skills、内置工具启用、Agent 白名单、工作目录、超时和脱敏。

验收标准：

- 高风险工具默认关闭。
- 未授权 MCP/Skill 返回 `TOOL_NOT_ALLOWED` 或等价错误。
- shell/file/network/MCP 外部服务有明确边界。
- 环境门控不通过时能力不可见。

### BE-14 工具调用事件与落库

目标：

- 支持 `tool_call_started`、`tool_call_delta`、`tool_call_completed` SSE 事件和对应 parts/span 记录。

验收标准：

- 工具开始、成功、失败都可追踪。
- MCP 工具调用开始、成功、失败都可追踪。
- 工具结果长度受限。
- 普通用户视图不暴露敏感参数。

### FE-11 工具调用可视化

目标：

- 在消息中展示工具调用过程块。

验收标准：

- 普通用户看到工具名称、状态、摘要。
- 失败工具显示清晰错误。
- 详情抽屉可查看关联 span。

## 9. M7 Run/Span 与开发者调试

### BE-15 agent_run_span

目标：

- 新增 span 记录上下文组装、模型调用、工具调用、落库和 SSE。

验收标准：

- Run 详情能返回 span 时间线。
- span metadata 已脱敏。
- 失败 span 能关联错误摘要。

### BE-16 Run 查询接口

接口：

- `GET /api/agent/runs/{runId}`
- `GET /api/agent/sessions/{sessionId}/runs?messageId=`

验收标准：

- 当前用户只能查看自己的 Run。
- 开发者详情字段可通过 profile 或内部开关控制。

### FE-12 开发者调试视图

目标：

- 增加内部调试视图，展示会话运行链路。

验收标准：

- 可按会话查看 Run 列表。
- 可查看 Run/Span 时间线。
- 可查看工具调用摘要和错误链路。
- 默认不在普通用户页面暴露入口，或通过内部开关展示。

### QA-03 真实链路验收

要求：

- 使用 `source/htam-agent-platform/.env` 中的真实 LLM 配置。
- 验证 `openai-compatible` 普通发送。
- 验证重新生成和编辑重发。
- 验证慢速流式增量。
- 验证模型切换。
- 验证 `agentscope-react` 受控 MCP/Skills 链路。
- 验证同一 Agent 授权给多个用户时，记忆和运行记录隔离。
- 验证取消生成后锁释放。
- 验证 Run/Span/token/耗时落库。

### QA-04 安全检查

检查项：

- 文档、日志、测试和前端普通视图不出现 API Key、token、数据库密码。
- 工具调用参数和输出已脱敏或截断。
- 不同 `userCode` 不能互查会话、消息、记忆、Run。

## 10. 开发顺序建议

建议严格按里程碑推进：

1. 先做 M1，确定用户、Agent、授权、能力和记忆底座。
2. 再做 M2，确保当前主链路可靠并按 Agent 授权运行。
3. M3 补齐用户高频能力和运行记录。
4. M4 单独处理前端重构，避免与大量功能开发交叉。
5. M5 完成 Provider 基础后再接 M6 ReAct、MCP 和 Skills。
6. M7 在 M6 之后补全工具和运行链路可视化。
7. M8 用真实链路做最终验收，不能只依赖 mock provider 或静态页面。

每个里程碑完成后应保留测试结果和关键截图。UI 变更需要补充桌面端和窄屏截图。
