# V2 第一轮执行步骤

> 注意：本文档为历史阶段文档，仅作为需求、调研和演进参考。
> 当前 Agent 中台架构与后续开发以 `docs/v3-agent中台/` 为准。
> AI agent 执行开发任务前必须先阅读 `docs/README.md` 和 V3 架构文档。

> 日期：2026-05-15
> 依据：V2 需求、技术方案、详细设计和开发计划
> 目标：先交付“Agent 授权 + 用户隔离记忆 + 会话绑定 Agent + 原流式主链路可用”的最小平台闭环，再扩大并行开发范围。

## 1. 执行策略

第一轮不一次性实现完整 V2。先打通通用 Agent 平台底座：

- 平台内部用户：`agent_user`
- Agent 定义：`agent_definition`
- Agent 授权：`agent_user_grant`
- 能力定义：`agent_capability`
- Agent 能力白名单：`agent_definition_capability`
- 用户隔离记忆：`agent_memory`
- 会话、消息、Run 绑定 `agent_id`
- 默认通用 Agent
- 授权用户可以进入 Agent 对话
- 未授权用户不能访问 Agent、会话、记忆、Run
- 原有流式对话保持可用，并逐步迁移到 `run_started` JSON envelope

## 2. 工作方式

- 使用独立 worktree 和分支：`feature/v2-agent-platform`
- 主控负责 schema、共享契约、合并、测试和质量门。
- 多 agent 只在契约稳定后并行，且每个 agent 拥有明确写入范围。
- 每个任务必须先写测试，再实现，再 review。

## 3. 第一轮任务

### Task A：Schema + 基础 DTO，串行

写入范围：

- `source/htam-agent-platform/agent-api/src/main/java/com/htam/agent/api/...`
- `source/htam-agent-platform/agent-web/src/main/resources/db/migration/...`

交付：

- 新增用户、Agent、授权、能力、记忆表。
- `agent_session`、`agent_message`、`agent_run` 目标结构带 `agent_id`。
- DTO 包含 `AgentSummary`、`AgentDetail`、`AgentMemory`、`PagedResult`。
- Flyway migrate 和 DTO 序列化测试通过。

### Task B：Agent 授权后端

写入范围：

- `agent-core/src/main/java/com/htam/agent/core/agent/...`
- `agent-web/src/main/java/com/htam/agent/web/agent/...`

交付：

- `AgentDefinitionService`
- `AgentAccessService`
- `GET /api/agent/agents`
- `GET /api/agent/agents/{agentId}`
- 未授权访问返回明确错误。
- 测试覆盖用户只能看到授权 Agent。

### Task C：用户隔离记忆

写入范围：

- `agent-core/src/main/java/com/htam/agent/core/memory/...`
- `agent-web/src/main/java/com/htam/agent/web/memory/...`

交付：

- `AgentMemoryService`
- `GET /api/agent/agents/{agentId}/memories`
- `DELETE /api/agent/agents/{agentId}/memories`
- 只读/清空当前 `userCode + agentId` 的记忆。
- 测试覆盖同一 Agent 下两个用户记忆隔离。

### Task D：会话绑定 Agent + 主链路授权

写入范围：

- `ChatService`
- `ChatRepository`
- `ChatController`
- 会话/消息 DTO

交付：

- 新建会话必须绑定 `agentId`，未传时使用默认授权 Agent。
- 发送消息前校验 `userCode + agentId` 授权。
- 列表、消息查询、删除都按 `userCode + agentId` 隔离。
- 测试覆盖未授权 Agent 不能创建会话、发送消息或查询消息。

### Task E：Run 优先 + JSON envelope SSE

写入范围：

- `agent-core/run/...`
- `ChatService`
- `ChatController`
- 前端 SSE parser

交付：

- 每次发送先创建 Run。
- SSE 输出 `run_started`、`thinking_delta`、`message_delta`、`run_completed`、`error`。
- `run_started` 后前端替换本地 ID。
- 测试覆盖 SSE `data` 全部 JSON，事件顺序稳定。

### Task F：前端 Agent 选择最小 UI

写入范围：

- `source/htam-agent-platform-ui/src/api.ts`
- `source/htam-agent-platform-ui/src/types.ts`
- `source/htam-agent-platform-ui/src/App.vue`

交付：

- 加载授权 Agent 列表。
- 新建会话绑定当前 Agent。
- 显示当前 Agent 名称和能力摘要。
- 可查看/清空当前 Agent 记忆摘要。
- 保持现有聊天体验可用。

## 4. 并行策略

第一阶段串行：

- Task A
- Task D/E 的共享契约部分

第二阶段最多并行 3 个 worker：

- Worker 1：Task B Agent 授权
- Worker 2：Task C 记忆
- Worker 3：Task F 前端 Agent UI

主控保留：

- schema 和迁移合并
- 主链路授权
- SSE 协议切换
- 全量测试和最终 review

## 5. 质量门

每个任务完成标准：

- 先写测试，确认失败。
- 实现最小代码。
- 运行对应模块测试。
- 做规格符合性 review。
- 做代码质量 review。
- 不写入真实 API Key、token、数据库密码。
- 所有接口校验 `userCode + agentId`。
- 所有 SSE `data` 为 JSON。

最终验证：

```bash
cd source/htam-agent-platform
mvn test

cd ../htam-agent-platform-ui
npm test
npm run build
```

真实 LLM smoke test 在主链路稳定后执行。
