# 通用大模型对话 V2 需求

> 注意：本文档为历史阶段文档，仅作为需求、调研和演进参考。
> 当前 Agent 中台架构与后续开发以 `docs/v3-agent中台/` 为准。
> AI agent 执行开发任务前必须先阅读 `docs/README.md` 和 V3 架构文档。

> 版本：v2
> 日期：2026-05-15
> 依据：`docs/v1-通用大模型对话/评审/综合对比分析汇总.md`、V1 需求/技术方案/详细设计、当前 `source/htam-agent-platform` 与 `source/htam-agent-platform-ui` 实现状态
> 定位：面向首次上线目标架构，在当前 V1 实现基础上建设“带用户管理的 OpenClaw + Hermes Agent”式通用 Agent 对话平台底座。

## 1. 背景

当前代码已完成 Web 端通用对话的基础闭环，包括会话管理、文本消息发送、前端排队、thinking 展示、SSE 输出和消息持久化。项目尚未正式上线，因此 V2 不需要为未发布的 V1 HTTP/SSE/数据库契约保留兼容层，可以直接按首次上线目标架构收敛 API、SSE、数据模型和前端状态模型。评审汇总确认，当前实现具备继续迭代的基础，但与 Open-WebUI、LobeChat 和 AgentScope Studio 相比，仍存在四类系统性差距：

- **核心交互不足**：缺少代码高亮、重新生成、编辑重发、会话重命名、会话搜索、导出、主题切换和快捷键。
- **工程基建不足**：上游模型调用并非真正流式，流式消息使用本地临时 ID，缺少上下文长度保护、分页和多 Provider。
- **Agent 平台能力不足**：当前生产路径直接调用 OpenAI-compatible API，尚未通过 `ReActAgent`、`SkillBox`、`AgentSkill` 承载可配置技能。
- **运行可观测不足**：只有会话和消息，没有 Run/Span、token usage、耗时、调用链、工具执行过程和开发者调试视图。

最终产品定位不是单纯的“聊天 UI”，而是一个具备用户管理、用户隔离记忆、Agent 能力配置、MCP/Skills 工具调用和 Agent 授权分发能力的通用 Agent 对话平台。可以理解为：在 Web 产品形态上提供用户可用的通用 Agent 对话，在运行时能力上吸收 OpenClaw 的 Agent 路由、技能白名单和安全边界，在记忆与自改进方向上吸收 Hermes Agent 的用户画像、长期记忆和技能化能力。

V2 采用“平台底座版”范围，覆盖评审汇总中的 P0、P1、P2，同时把“用户 - Agent - 记忆 - 能力授权”作为首次上线的数据和运行时主线。V2 不只做短期体验修复，也为后续多 Agent、授权给不同用户、评估和平台化运营建立基础模型。

V2 的上线前架构策略是：允许破坏性调整未发布契约，统一采用分页响应、Run 优先建模、JSON envelope SSE、`AgentRuntime` 运行时抽象和重整后的 Flyway baseline；正式上线后再进入只追加迁移、只兼容演进的模式。

## 2. 目标

V2 面向两个使用群体：

- **普通对话用户**：使用被授权的通用 Agent，与其进行带独立记忆的多轮对话。
- **Agent 管理员/平台管理员**：配置 Agent、模型、MCP server、skills、记忆策略和用户授权。
- **平台开发者**：查看模型调用、运行链路、错误和工具执行过程，支撑问题定位和能力扩展。

V2 目标包括：

- 上游模型响应必须真正逐块转发，降低首 token 延迟。
- 前端流式消息必须在收到 `run_started` 后使用后端权威消息 ID，刷新和锚点定位后保持一致。
- 支持消息重新生成、用户消息编辑重发、会话手动重命名、会话搜索、会话复制、会话收藏和文本导出。
- 支持完整 Markdown 基础渲染能力，包括代码语法高亮和表格。
- 支持深色/浅色主题切换、常用快捷键和更完整的消息操作栏。
- 会话列表和消息列表支持分页，避免长会话和大量历史会话一次性加载。
- 上下文组装具备 token 预算保护，避免超出模型上下文窗口后直接失败。
- 支持多 Provider 和模型切换，保留 OpenAI-compatible 普通模型路径，并新增 AgentScope ReAct 运行时路径。
- 支持 `AgentRuntime` 运行时抽象，普通模型对话和 `ReActAgent` 技能化运行都通过统一运行时事件输出。
- 支持基础 Agent 管理模型，包括通用 Agent 定义、Agent 能力配置、Agent 与用户授权关系。
- 支持用户隔离记忆，每个用户使用同一个 Agent 时拥有独立记忆，不与其他用户共享。
- 支持 MCP 与 Skills 统一纳入能力注册、白名单、授权、审计和运行可观测。
- 建立 Run/Span 可观测模型，记录本轮运行、模型调用、token、耗时、错误和工具调用过程。
- 提供内部消息/运行详情抽屉和开发者调试视图，普通用户页面不暴露敏感调试信息。
- 前端从单文件巨石组件演进为组件化结构，并引入 Pinia 管理会话、消息、流式状态和偏好设置。

## 3. 用户体验需求

### 3.1 消息展示

- 用户只能看到自己被授权使用的 Agent，并在进入对话前选择或使用默认 Agent。
- 会话页面展示当前 Agent 名称、简介、模型和可用能力摘要。
- 助手消息支持 Markdown 段落、标题、列表、引用、行内代码、代码块和表格。
- 代码块支持语法高亮、复制代码和横向滚动。
- thinking 内容仍与最终回复分区展示，默认策略沿用 V1：生成中展开，完成后可折叠。
- 工具调用事件在普通用户页以简洁过程块展示，不展示敏感参数；开发者视图可查看更完整的工具调用详情。
- 流式生成过程中，消息 ID 在收到 `run_started` 事件后替换为后端 `userMessageId` 和 `assistantMessageId`。

### 3.2 消息操作

- 用户可以复制消息文本。
- 用户可以对助手回复重新生成。
- 用户可以编辑历史用户消息并重新生成后续助手回复。
- 用户可以删除单条消息；删除后不影响审计数据，普通用户视角不可见。
- 用户可以在支持的消息上查看运行详情，包括模型、耗时、token、错误摘要和关联工具调用。
- 当当前会话正在生成时，与当前会话冲突的编辑、删除、重新生成操作应禁用或提示等待当前生成完成。

### 3.3 会话组织

- 会话必须绑定一个 `agentId`，同一用户可以分别与不同 Agent 建立会话。
- 用户可以手动重命名会话。
- 用户可以搜索当前用户的历史会话。
- 用户可以收藏会话，收藏会话在列表中优先展示或可通过筛选查看。
- 用户可以复制会话，复制后生成新的会话及消息副本。
- 用户可以导出会话文本。V2 默认支持 Markdown/纯文本导出，截图和 PDF 可作为后续扩展。
- 会话列表支持分页或游标加载，不再一次性返回全部历史会话。

### 3.4 输入与快捷键

- `Enter` 发送，`Shift+Enter` 换行。
- `Ctrl/Command+N` 新建会话。
- `Ctrl/Command+R` 对当前最后一条助手消息重新生成。
- `Ctrl/Command+K` 聚焦会话搜索。
- `Ctrl/Command+Enter` 将输入追加到队列但不立即发送；如果当前无生成中任务，则作为待发送草稿保留。
- 快捷键不得破坏浏览器和输入法常用行为；输入框聚焦时优先保护文本编辑体验。

### 3.5 主题与偏好

- 支持浅色、深色和跟随系统三种主题策略。
- 用户偏好保存在浏览器本地；V2 不要求服务端保存主题偏好。
- 模型选择、详情抽屉开关、thinking 折叠状态可在前端保存会话内或本地偏好。

### 3.6 记忆管理

- 每个用户拥有按 Agent 隔离的独立记忆。
- V2 默认支持可解释的文本型记忆，包括用户偏好、长期事实、阶段性摘要和 Agent 对用户的操作约定。
- 用户可以查看当前 Agent 对自己的记忆摘要。
- 用户可以删除或清空某个 Agent 下属于自己的记忆。
- Agent 在生成前只能读取当前 `userCode + agentId` 范围内允许注入的记忆。
- 记忆写入必须经过运行时策略控制，V2 不允许工具或模型绕过服务端直接写入其他用户记忆。

## 4. 后端能力需求

### 4.0 用户、Agent 与授权

- V2 建立平台内部用户模型，当前仍可由 `X-App-Code` 映射为 `userCode`，但数据模型不再把 `appCode` 等同于长期用户体系。
- V2 建立 Agent 定义模型，至少包含名称、描述、运行时类型、默认模型、系统提示词、启用的 MCP/Skills、记忆策略和状态。
- V2 建立 Agent 授权模型，控制哪些用户可以看到和使用哪些 Agent。
- 用户创建会话、发送消息、查看历史、读取记忆和查看运行详情时，都必须校验 `userCode + agentId` 授权。
- 同一个 Agent 被授权给多个用户时，Agent 配置共享，用户会话、用户记忆和运行记录隔离。

### 4.1 真正流式

- OpenAI-compatible 路径不得使用完整响应体聚合后再解析的方式实现流式。
- 后端必须逐块读取上游 SSE，并尽快映射为前端 SSE 事件。
- 前后端 SSE 统一使用 JSON envelope，事件至少包含 `eventId`、`runId`、`sessionId`、`messageId`、`sequence`、`createdAt`。
- V2 正式事件名采用 `run_started`、`thinking_delta`、`message_delta`、`tool_call_started`、`tool_call_delta`、`tool_call_completed`、`span_started`、`span_completed`、`span_failed`、`run_completed`、`run_failed`、`error`。
- 上游异常、连接中断、客户端取消必须释放会话锁，并将未完成助手消息置为失败或由清理机制兜底。

### 4.2 分页与搜索

- 会话列表支持分页、关键词搜索、收藏筛选。
- 消息列表支持分页或游标加载，并保证按会话内顺序稳定返回。
- 上下文组装不依赖前端已加载消息，必须从数据库按规则读取权威历史。

### 4.3 上下文保护

- `ContextAssembler` 增加 token 预算配置。
- V2 默认采用保留最近 N 轮 + 粗略 token 估算的保护策略。
- 当历史过长时，服务端应截断较早历史并记录上下文裁剪信息。
- V2 不强制实现自动摘要，但保留 `summary_message_id` 与后续摘要边界语义。

### 4.4 多 Provider 与模型切换

- 支持配置多个 Provider 和模型。
- Provider 至少包含：
  - `openai-compatible`：普通模型对话路径。
  - `agentscope-react`：基于 AgentScope `ReActAgent` 的技能化路径。
- 前端允许用户在会话级选择模型；会话创建后默认使用系统默认模型。
- 已有会话切换模型时，新一轮消息使用新模型，历史消息保留原模型记录。
- Provider 配置错误必须 fail closed，不静默回退到其他模型。

### 4.5 ReActAgent、MCP 与 Skills 能力运行时

- V2 新增 `AgentRuntime` 运行时抽象，`OpenAiChatRuntime` 承载普通模型对话，`AgentScopeReActRuntime` 承载 `ReActAgent.stream(..., StreamOptions.incremental(true))`。
- `LlmProviderAdapter` 只处理 OpenAI-compatible、Anthropic、Ollama 等底层模型协议差异，不直接承载 Agent 工具编排语义。
- MCP server 和 Skills 统一由 `CapabilityRegistry` 或等价能力注册中心管理。
- Agent 配置只引用允许的 MCP/Skills 能力，用户实际运行时还要叠加用户授权、环境可用性和安全策略。
- 技能由 `SkillRegistry` 或等价配置管理，MCP 由 `McpRegistry` 或等价配置管理，默认关闭高风险能力。
- 文件、shell、网络、MCP 外部服务等能力必须有启用开关、工作目录/目标域名白名单、权限审计、超时和错误脱敏。
- Agent 内存只作为单次运行辅助，不作为跨用户、跨会话的权威长期记忆；数据库仍是会话上下文权威来源。
- 用户长期记忆由服务端记忆模块控制，运行时只能通过受控接口读取或写入当前用户当前 Agent 的记忆。

### 4.6 运行可观测

- 每次用户触发模型生成、重新生成或编辑重发，都创建一个 Run。
- Run 记录会话、用户消息、助手消息、Provider、模型、状态、开始时间、结束时间、首 token 延迟、总耗时、token usage 和错误摘要。
- Span 记录运行内部步骤，例如上下文组装、模型调用、工具调用、落库、SSE 输出。
- DB Run/Span 用于产品侧查询和审计摘要，OpenTelemetry trace 用于运行诊断；两者通过 `traceId`、`runId`、`spanId` 关联。
- V2 不单独要求 `agent_tool_call` 表，工具过程先由 `agent_run_span` 和 `agent_message_part` 承载，后续出现独立检索或审计报表需求时再拆表。
- 普通用户可查看简化运行详情；开发者/管理员可查看更完整的运行链路。

### 4.7 上线前迁移策略

- 项目正式上线前，可重整 Flyway baseline，形成面向首次上线的清晰初始化脚本。
- 进入共享联调库或上线环境后，不再重写已执行迁移，只允许追加新版本迁移。
- V2 文档中的数据字段是首次上线目标 schema，不要求以兼容旧库的 `alter table` 形式表达。

## 5. 非 V2 范围

以下能力不纳入 V2 正式范围：

- 企业级账号体系、SSO/OIDC、LDAP、复杂 RBAC 和用户组同步。
- 文件上传、图片输入、语音输入输出和多模态生成。
- 知识库/RAG、向量检索和跨用户共享知识库。
- 自动记忆提炼、梦境系统、后台学习闭环和技能自创建。
- 分支对话完整树模型和 Artifacts 实时预览。
- 多入口接入，包括移动端、WebSocket、Webhook、消息渠道和开放 API Key。
- 自动评测、多 Run 对比报表和模型效果回归平台。
- 直接嵌入 AgentScope Studio 到生产用户页面。

## 6. 验收标准

- 慢速上游模型输出时，前端能持续收到增量片段，而不是等待完整响应后一次性输出。
- SSE `data` 全部是 JSON envelope，不再混用纯文本片段和 JSON 对象。
- 流式完成后刷新页面，用户消息和助手消息使用数据库 ID 正常恢复，锚点定位可用。
- 重新生成、编辑重发、重命名、搜索、收藏、复制和导出按当前 `userCode` 隔离。
- 用户只能看到和使用授权给自己的 Agent。
- 同一 Agent 授权给多个用户时，不同用户的会话、记忆和运行记录互相不可见。
- 长会话不会因无保护拼接全部历史而直接触发上下文窗口错误。
- 会话和消息分页契约稳定，前端支持继续加载。
- 选择不同模型后，新消息记录正确的模型名和 Provider。
- `agentscope-react` 运行时可在受控技能配置下完成一次真实流式对话，并记录 Run。
- 一个 Agent 可配置至少一个 Skill 或 MCP 能力，并在授权用户对话中按白名单执行。
- 用户可查看和清空自己在某个 Agent 下的记忆摘要。
- Run/Span 能展示模型名、耗时、token、错误和工具调用摘要。
- 普通用户页面不暴露 API Key、token、数据库密码、完整工具参数等敏感信息。
- 前端组件化后，当前已实现的会话 CRUD、排队、thinking、停止生成、锚点导航和失败态不回退。
