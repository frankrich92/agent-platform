# 通用大模型对话 V2 详细设计

> 注意：本文档为历史阶段文档，仅作为需求、调研和演进参考。
> 当前 Agent 中台架构与后续开发以 `docs/v3-agent中台/` 为准。
> AI agent 执行开发任务前必须先阅读 `docs/README.md` 和 V3 架构文档。

> 版本：v2
> 日期：2026-05-15
> 依据文档：`01-通用大模型对话V2需求.md`、`02-通用大模型对话V2技术方案.md`
> 目标：把 V2 能力拆成明确的数据模型、接口契约、核心流程和前端结构，指导后续代码开发。

## 1. 设计目标

V2 面向首次上线目标架构，在当前 V1 实现基础上建设通用 Agent 对话平台底座：

- 产品形态：带用户管理的 OpenClaw + Hermes Agent，用户只能使用被授权 Agent。
- 对话体验：Markdown 增强、代码高亮、重新生成、编辑重发、会话搜索、重命名、收藏、复制、导出、主题和快捷键。
- 流式质量：上游模型真正逐块读取，前端使用后端权威消息 ID。
- 运行时：多 Provider、模型切换、上下文预算保护、`AgentRuntime` 抽象、AgentScope ReAct 运行路径、MCP/Skills 能力调用。
- 用户隔离：同一个 Agent 授权给多个用户时，会话、消息、记忆、Run/Span 按 `userCode + agentId` 隔离。
- 可观测：Run/Span、token usage、耗时、错误、工具调用和消息/运行详情。
- 前端架构：组件化拆分，Pinia 管理状态，降低 `App.vue` 巨石组件风险。

项目尚未正式上线，V2 不为未发布的 V1 HTTP/SSE/数据库契约保留兼容层。本文档中的 API、SSE 和 schema 均按首次上线目标形态设计；上线前可重整 Flyway baseline，上线后再进入只追加迁移和只兼容演进的模式。

V2 继续使用当前请求头接入方式：`X-Token`、`X-App-Code` 必填。`X-App-Code` 在 V2 可继续映射为 `userCode`，但数据模型新增平台用户、Agent 定义和 Agent 授权关系，避免长期把 `appCode` 直接等同于正式用户体系。

### 2.2 核心服务

- `SessionService`：会话列表、搜索、分页、重命名、收藏、复制、删除。
- `MessageService`：消息分页、删除、内容组装、导出数据读取。
- `ChatService`：发送、重新生成、编辑重发、锁控制、SSE 业务编排。
- `AgentDefinitionService`：Agent 定义、运行时类型、默认模型、系统提示词、记忆策略和状态。
- `AgentAccessService`：校验 `userCode + agentId` 授权，控制用户可见和可用 Agent。
- `AgentMemoryService`：按 `userCode + agentId` 管理用户隔离记忆。
- `ContextAssembler`：上下文组装、token 估算、裁剪记录。
- `AgentRuntime`：统一普通模型对话、ReActAgent 对话和后续工具型 Agent 的运行时接口。
- `OpenAiChatRuntime`：普通 OpenAI-compatible 对话运行时，内部调用底层 provider adapter。
- `AgentScopeReActRuntime`：AgentScope `ReActAgent` 技能化运行路径。
- `LlmProviderAdapter`：底层模型协议适配，只处理 OpenAI-compatible、Anthropic、Ollama 等模型协议差异。
- `OpenAiCompatibleAdapter`：真正逐块读取上游 OpenAI-compatible SSE。
- `ProviderRegistry`：Provider 和模型选择。
- `CapabilityRegistry`：统一管理 MCP server、skills 和内置工具能力。
- `McpRegistry` / `McpClientManager`：MCP server 配置、连接、工具发现和调用。
- `SkillRegistry`：技能启用、工具白名单和运行策略。
- `RunService`：创建 Run、更新状态、记录 token 和耗时。
- `RunSpanRecorder`：记录模型调用、上下文组装、工具调用和落库等 span。
- `ConversationExportService`：导出 Markdown/文本。

## 3. 数据库设计

### 3.0 用户、Agent、能力与记忆

#### agent_user

保存平台内部用户。V2 可以由 `X-App-Code` 首次访问时自动映射或创建。

```sql
create table agent_user (
    id varchar(64) primary key,
    user_code varchar(128) not null unique,
    display_name varchar(128),
    status varchar(32) not null default 'active',
    source_type varchar(32) not null default 'mock_header',
    created_at timestamptz not null default now(),
    updated_at timestamptz not null default now()
);
```

#### agent_definition

保存可被授权给用户使用的 Agent 定义。

```sql
create table agent_definition (
    id varchar(64) primary key,
    code varchar(128) not null unique,
    name varchar(128) not null,
    description text,
    runtime_type varchar(64) not null,
    default_provider varchar(64) not null,
    default_model_name varchar(128) not null,
    system_prompt text,
    memory_policy varchar(64) not null default 'user_agent_text',
    status varchar(32) not null default 'active',
    created_at timestamptz not null default now(),
    updated_at timestamptz not null default now()
);
```

`runtime_type` 建议值：

- `openai-chat`
- `agentscope-react`

#### agent_user_grant

保存 Agent 授权关系。

```sql
create table agent_user_grant (
    id varchar(64) primary key,
    agent_id varchar(64) not null,
    user_code varchar(128) not null,
    grant_type varchar(32) not null default 'use',
    status varchar(32) not null default 'active',
    created_at timestamptz not null default now(),
    updated_at timestamptz not null default now(),
    constraint uk_agent_user_grant unique (agent_id, user_code, grant_type)
);

create index idx_agent_user_grant_user
    on agent_user_grant (user_code, status);
```

#### agent_capability

统一保存 MCP server、skill 和内置工具能力。

```sql
create table agent_capability (
    id varchar(64) primary key,
    code varchar(128) not null unique,
    capability_type varchar(32) not null,
    name varchar(128) not null,
    description text,
    config_json text,
    risk_level varchar(32) not null default 'normal',
    status varchar(32) not null default 'disabled',
    created_at timestamptz not null default now(),
    updated_at timestamptz not null default now()
);
```

`capability_type` 建议值：

- `mcp`
- `skill`
- `builtin_tool`

#### agent_definition_capability

保存 Agent 能力白名单。

```sql
create table agent_definition_capability (
    id varchar(64) primary key,
    agent_id varchar(64) not null,
    capability_id varchar(64) not null,
    status varchar(32) not null default 'active',
    created_at timestamptz not null default now(),
    constraint uk_agent_capability unique (agent_id, capability_id)
);
```

#### agent_memory

保存按用户和 Agent 隔离的文本型记忆。

```sql
create table agent_memory (
    id varchar(64) primary key,
    agent_id varchar(64) not null,
    user_code varchar(128) not null,
    memory_type varchar(32) not null,
    content text not null,
    source_run_id varchar(64),
    status varchar(32) not null default 'active',
    created_at timestamptz not null default now(),
    updated_at timestamptz not null default now()
);

create index idx_agent_memory_user_agent
    on agent_memory (user_code, agent_id, status, updated_at desc);
```

### 3.1 agent_session 扩展

V2 首次上线目标字段：

```sql
agent_id varchar(64) not null;
favorite boolean not null default false;
title_source varchar(32) not null default 'auto';
default_provider varchar(64);
default_model_name varchar(128);
```

字段说明：

- `agent_id`：会话绑定的 Agent。
- `favorite`：是否收藏。
- `title_source`：`auto` 或 `manual`，手动重命名后不再被自动标题覆盖。
- `default_provider`、`default_model_name`：会话级默认模型选择；为空时使用系统默认。

索引：

```sql
create index if not exists idx_agent_session_user_favorite_updated
    on agent_session (user_code, agent_id, favorite, status, updated_at desc);
```

搜索策略：

- V2 初期可使用 `title ilike`。
- 后续如需全文检索，再引入专用索引或搜索服务。

### 3.2 agent_message 扩展

V2 首次上线目标字段：

```sql
agent_id varchar(64) not null;
provider varchar(64);
run_id varchar(64);
parent_message_id varchar(64);
version integer not null default 1;
deleted boolean not null default false;
deleted_at timestamptz;
```

字段说明：

- `agent_id`：消息所属 Agent，与会话保持一致，便于审计和查询。
- `provider`：助手消息使用，记录模型路径。
- `run_id`：关联本次生成运行。
- `parent_message_id`：用于重新生成、编辑重发和后续分支扩展。
- `version`：同一用户消息多次生成时的版本标记。
- `deleted`：普通用户视角删除，不物理删除审计数据。

查询规则：

- 普通消息列表默认过滤 `deleted = false`。
- 上下文组装只使用 `status = completed` 且 `deleted = false` 的消息。
- 重新生成默认基于目标助手消息前的上下文创建新助手消息，并可将旧助手消息标记为 deleted 或保留为历史版本；V2 默认保留历史版本但普通列表只展示最新版本。

### 3.3 agent_run

```sql
create table agent_run (
    id varchar(64) primary key,
    agent_id varchar(64) not null,
    user_code varchar(128) not null,
    session_id varchar(64) not null,
    user_message_id varchar(64),
    assistant_message_id varchar(64),
    trace_id varchar(128),
    trigger_type varchar(32) not null,
    provider varchar(64) not null,
    model_name varchar(128) not null,
    status varchar(32) not null,
    prompt_tokens integer not null default 0,
    completion_tokens integer not null default 0,
    total_tokens integer not null default 0,
    first_token_latency_ms bigint,
    total_duration_ms bigint,
    context_message_count integer not null default 0,
    trimmed_message_count integer not null default 0,
    error_message text,
    created_at timestamptz not null default now(),
    started_at timestamptz,
    completed_at timestamptz
);

create index idx_agent_run_session_created
    on agent_run (user_code, session_id, created_at desc);

create index idx_agent_run_assistant_message
    on agent_run (assistant_message_id);
```

枚举：

- `trigger_type`：`send`、`regenerate`、`edit_resend`。
- `status`：`running`、`completed`、`failed`、`cancelled`。

### 3.4 agent_run_span

```sql
create table agent_run_span (
    id varchar(64) primary key,
    run_id varchar(64) not null,
    parent_span_id varchar(64),
    trace_id varchar(128),
    span_type varchar(64) not null,
    name varchar(128) not null,
    status varchar(32) not null,
    started_at timestamptz not null,
    ended_at timestamptz,
    duration_ms bigint,
    input_summary text,
    output_summary text,
    error_message text,
    metadata_json text,
    created_at timestamptz not null default now()
);

create index idx_agent_run_span_run_started
    on agent_run_span (run_id, started_at);
```

`span_type` 建议值：

- `context`
- `model`
- `tool_call`
- `persistence`
- `sse`
- `adapter`

`metadata_json` 只保存脱敏后的结构化信息。

V2 不单独创建 `agent_tool_call` 表。工具调用过程由 `agent_run_span` 记录执行链路，由 `agent_message_part` 记录面向用户展示的工具摘要。只有后续出现工具调用独立检索、重放、权限审计报表等明确需求时，再新增专用表。

DB Run/Span 用于产品侧查询和审计摘要，OpenTelemetry trace 用于运行诊断。两者通过 `trace_id`、`run_id`、`span_id` 关联。

## 4. API 详细设计

### 4.1 分页响应

统一分页响应：

```json
{
  "items": [],
  "nextCursor": "string-or-null",
  "hasMore": true
}
```

V2 使用游标分页。游标内容由服务端生成，前端不解析。

由于项目尚未上线，分页响应是 V2 首次上线正式契约，不保留旧数组响应。

### 4.2 会话列表

```text
GET /api/agent/sessions?pageSize=30&cursor=&keyword=&favorite=
```

返回：

```json
{
  "items": [
    {
      "id": "session-id",
      "title": "会话标题",
      "favorite": false,
      "defaultProvider": "openai-compatible",
      "defaultModelName": "model",
      "lastMessageAt": "2026-05-15T10:00:00Z",
      "updatedAt": "2026-05-15T10:00:00Z"
    }
  ],
  "nextCursor": null,
  "hasMore": false
}
```

规则：

- 只返回当前 `userCode` 且 `status = active` 的会话。
- `keyword` 只搜索标题。
- `favorite=true` 只返回收藏会话。
- 默认按 `favorite desc, updated_at desc` 排序。

### 4.3 更新会话

```text
PATCH /api/agent/sessions/{sessionId}
```

请求：

```json
{
  "agentId": "agent-id",
  "title": "新标题",
  "favorite": true,
  "defaultProvider": "openai-compatible",
  "defaultModelName": "model"
}
```

规则：

- 字段均可选，只更新传入字段。
- `title` 传入后 `title_source = manual`。
- `agentId` 只允许在新建会话时指定，已存在会话不允许切换 Agent。
- provider/model 必须来自当前可用模型列表。
- 用户不能更新不属于自己的会话。

### 4.4 复制会话

```text
POST /api/agent/sessions/{sessionId}/duplicate
```

规则：

- 复制当前用户可见的非删除消息和 parts。
- 新会话 `parent_session_id` 指向源会话。
- 新会话标题默认追加 ` 副本`。
- 复制后的消息保持 completed/failed 状态，不复制 streaming 消息。

### 4.5 导出会话

```text
GET /api/agent/sessions/{sessionId}/export?format=markdown
```

支持格式：

- `markdown`
- `text`

导出内容：

- 会话标题。
- 创建时间和导出时间。
- 用户消息、助手最终回复。
- thinking 默认不导出；开发者视图可另行查看。
- 工具调用默认只导出摘要。

### 4.6 消息分页

```text
GET /api/agent/sessions/{sessionId}/messages?pageSize=50&before=&after=
```

规则：

- 默认返回最近一页并按 `sequence asc` 展示。
- `before` 用于向更早历史加载。
- 返回消息包含 parts，parts 按 `part_sequence asc`。
- 默认过滤 `deleted = false`。

### 4.7 普通发送

```text

Content-Type: application/json
```

请求：

### 4.8 重新生成

```text
POST /api/agent/sessions/{sessionId}/messages/{assistantMessageId}/regenerate
Accept: text/event-stream
```

请求：

```json
{
  "provider": "openai-compatible",
  "modelName": "model",
  "replaceLatest": true
}
```

规则：

- 目标消息必须是当前用户会话中的助手消息。
- 基于该助手消息关联的用户消息重新生成。
- 默认 `replaceLatest = true`：旧助手消息在普通列表中隐藏，新助手消息展示为最新版本。
- 历史版本仍保留用于审计和后续分支能力。

### 4.9 编辑重发

```text
POST /api/agent/sessions/{sessionId}/messages/{userMessageId}/edit-and-resend
Accept: text/event-stream
```

请求：

```json
{
  "content": "编辑后的用户消息",
  "provider": "openai-compatible",
  "modelName": "model"
}
```

规则：

- 不直接覆盖原用户消息；创建新的用户消息版本。
- 原用户消息及其后续普通展示消息可标记隐藏，保留审计。
- 基于编辑后的用户消息重新生成助手回复。
- 若当前会话正在生成，返回 `SESSION_BUSY`。

### 4.10 删除消息

```text
DELETE /api/agent/sessions/{sessionId}/messages/{messageId}
```

规则：

- 普通删除为 `deleted = true`。
- 删除用户消息时，默认同时隐藏由该消息触发的直接助手回复。
- 不物理删除 parts、run、span。

## 5. 流式核心流程

### 5.1 普通发送

1. Controller 校验请求头和 session 归属。
2. `AgentAccessService` 校验当前用户对会话绑定的 `agentId` 有使用授权。
3. `ChatService` 非阻塞获取会话锁。
4. 创建 Run，并创建用户消息、助手 streaming 消息，三者互相关联。
5. 返回 `run_started` 事件，包含权威消息 ID、`runId` 和 `agentId`。
6. `AgentDefinitionService` 读取 Agent 配置。
7. `AgentMemoryService` 读取当前 `userCode + agentId` 的可注入记忆。
8. `ContextAssembler` 读取数据库历史、记忆和系统提示词并按预算裁剪。
9. `CapabilityRegistry` 根据 Agent 白名单、用户授权、环境门控和安全策略裁剪 MCP/Skills 能力。
10. `ProviderRegistry` / `ModelRegistry` 校验请求或 Agent 默认模型。
11. `AgentRuntime` 根据运行时类型输出 `AgentStreamEvent`。
12. `ChatService` 将 thinking/text/tool parts 增量落库，并记录 Run/Span。
13. 完成时更新助手消息、Run、session 统计并发送 `run_completed`。
14. 异常或取消时更新失败态、释放锁并发送或记录错误。

### 5.2 重新生成

1. 校验目标助手消息归属和状态。
2. 找到对应用户消息和目标消息之前的上下文边界。
3. 创建新的助手消息和 Run。
4. 默认隐藏旧助手消息的普通展示版本。
5. 复用普通发送的 runtime、落库和 SSE 流程。

### 5.3 编辑重发

1. 校验目标用户消息归属。
2. 创建新的用户消息版本，内容为编辑后文本。
3. 隐藏原消息后续需要替换的普通展示消息。
4. 创建新的助手消息和 Run。
5. 复用普通发送的 runtime、落库和 SSE 流程。

## 6. Runtime 与 Provider 详细设计

### 6.1 AgentRuntime 接口

```java
public interface AgentRuntime {
    Flux<AgentStreamEvent> stream(AgentRunRequest request);
}
```

`AgentRunRequest` 包含：

- `runId`
- `runtimeType`
- `provider`
- `modelName`
- `messages`
- `systemPrompt`
- `skills`
- `mcpServers`
- `memory`
- `traceContext`
- `options`

`AgentStreamEvent` 类型：

- `thinking_delta`
- `message_delta`
- `tool_call_started`
- `tool_call_delta`
- `tool_call_completed`
- `span_started`
- `span_completed`
- `span_failed`
- `run_completed`
- `run_failed`
- `error`

### 6.2 LlmProviderAdapter 接口

```java
public interface LlmProviderAdapter {
    Flux<LlmProviderEvent> stream(LlmProviderRequest request);
}
```

`LlmProviderAdapter` 是底层模型协议适配，不直接表达 Agent 工具编排。`OpenAiChatRuntime` 可以调用该接口，把底层模型事件转换为统一 `AgentStreamEvent`。

### 6.3 OpenAI-compatible

实现要求：

- 使用真正逐块读取。
- 兼容 `data: [DONE]`。
- 兼容 thinking 字段差异，不能把 thinking 与最终文本混在同一个 message part。
- 响应 token usage 如果只在最终事件出现，应在 `provider_completed` 转换为 `run_completed` 时补齐 Run。
- JSON 解析异常需要带上脱敏摘要。

### 6.4 AgentScope ReAct

实现要求：

- 每次请求构建本次运行所需的 Agent 和工具集合，避免跨用户状态污染。
- 使用数据库上下文作为输入，不依赖 Agent 内存恢复历史。
- 只注入当前 `userCode + agentId` 的用户记忆。
- 只暴露当前 Agent 白名单和用户授权允许的 MCP/Skills。
- `ReActAgent.stream` 输出事件统一转成 `AgentStreamEvent`。
- 工具调用开始、结果、失败都记录 span。
- 工具输出需要长度限制和脱敏。

### 7.2 Store 职责

- `authStore`：读取 URL、保存 token/appCode、提供请求头。
- `sessionStore`：会话分页、搜索、收藏、重命名、复制、删除、当前会话。
- `messageStore`：消息分页、临时消息、ID 替换、消息隐藏、parts 更新。
- `streamStore`：当前流、AbortController、队列、重新生成、编辑重发。
- `preferenceStore`：主题、模型选择、详情抽屉、thinking 展开偏好。

### 7.3 本地 ID 替换

发送前：

- 创建 `local-user-*` 和 `local-assistant-*` 临时消息。

收到 `run_started` 后：

- 将本地用户消息 ID 替换为 `userMessageId`。
- 将本地助手消息 ID 替换为 `assistantMessageId`。
- 保存 `runId`、provider、modelName。
- 锚点、消息操作和后续 parts 追加全部使用权威 ID。

流完成后：

- 可刷新当前会话消息页或使用 SSE 累积内容作为乐观状态。
- 若刷新结果与本地状态冲突，以后端返回为准。

### 7.4 Markdown 与代码高亮

- 使用成熟 Markdown 渲染库，支持表格。
- 代码高亮可使用 `highlight.js` 或 `shiki`，优先选择与当前构建成本更低的方案。
- 渲染 HTML 必须经过安全处理，禁止直接插入未净化 HTML。
- 代码块提供复制按钮。

### 7.5 运行详情抽屉

入口：

- 助手消息操作栏的“详情”按钮。
- 错误消息的“查看详情”。

展示：

- Run 状态、Provider、模型。
- token usage。
- 首 token 延迟、总耗时。
- 上下文消息数和裁剪消息数。
- Span 时间线。
- 错误摘要。
- 工具调用摘要。

普通用户默认不展示完整工具参数和原始 metadata。

## 8. 错误处理

新增错误码：

- `SESSION_NOT_FOUND`
- `MESSAGE_NOT_FOUND`
- `RUN_NOT_FOUND`
- `PROVIDER_NOT_FOUND`
- `MODEL_NOT_AVAILABLE`
- `CONTEXT_TOO_LONG`
- `TOOL_NOT_ALLOWED`
- `TOOL_EXECUTION_FAILED`
- `RUN_FAILED`

错误响应仍使用：

```json
{
  "code": "ERROR_CODE",
  "message": "错误摘要",
  "traceId": "trace-id"
}
```

SSE 建连后的错误使用 `error` 事件，并同步更新 Run 和助手消息状态。
