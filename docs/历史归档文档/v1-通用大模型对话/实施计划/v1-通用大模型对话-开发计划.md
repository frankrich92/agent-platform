# 通用大模型对话 V1 开发计划

> 注意：本文档为历史阶段文档，仅作为需求、调研和演进参考。
> 当前 Agent 中台架构与后续开发以 `docs/v3-agent中台/` 为准。
> AI agent 执行开发任务前必须先阅读 `docs/README.md` 和 V3 架构文档。

> 版本：v1
> 日期：2026-05-14
> 依据文档：`01-通用大模型对话需求.md`、`02-通用大模型对话技术方案.md`、`04-通用大模型对话详细设计.md`
> 目标：把当前设计拆解为可执行开发任务，保持 V1 范围稳定，不引入非首版 Agent 平台能力。

## 1. V1 范围锁定

V1 只实现 Web 端基础通用对话：

- URL `token/appCode` 入口。
- 最小鉴权与 `userCode = appCode` mock 隔离。
- 会话新建、列表、打开、删除。
- 文本消息发送。
- SSE 流式回复。
- thinking 与最终回复分区展示。
- 历史消息恢复和续聊。
- 响应中消息前端排队。
- 助手失败态、自动发送失败态、客户端断开处理。

以下能力不进入 V1：

- 正式账号体系、生产鉴权、模型切换、会话搜索、长期记忆、上下文压缩、Agent 工具、插件、子 Agent、多入口、定时任务、Gateway、Lane Queue、sandbox。

## 2. 总体实施顺序

1. 后端工程骨架。
2. 数据库与迁移。
3. API 契约与基础错误模型。
4. 鉴权与用户上下文。
5. 会话与消息基础接口。
6. LLM provider 与上下文组装。
7. 流式发送主链路。
8. 前端工程骨架。
9. 前端会话与消息 UI。
10. 前端 SSE、排队、失败态。
11. 联调与回归测试。

最终测试约束：

- 单元测试和组件级集成测试可以使用 mock provider、stub SSE 或本地假实现。
- M5 联调验收必须走真实大模型链路，使用 `source/htam-agent-platform/.env` 中的 `HTAM_LLM_*` 配置调用实际模型服务。
- 最终验收不得只以 mock provider、启动上下文测试、接口桩或静态页面验证作为通过依据。
- 真实链路至少覆盖首轮发送、流式增量、thinking/message 分区、done 结束、消息落库、刷新恢复、会话锁释放和异常失败态。

## 3. 后端任务

### BE-01 工程骨架

目标：

- 创建 `source/htam-agent-platform` Maven 多模块工程。
- 模块包括 `agent-api`、`agent-core`、`agent-web`。
- 固定 JDK 21、Spring Boot 4.0.5、`agentscope-java` 1.0.12。

涉及范围：

- `source/htam-agent-platform/pom.xml`
- `source/htam-agent-platform/agent-api/pom.xml`
- `source/htam-agent-platform/agent-core/pom.xml`
- `source/htam-agent-platform/agent-web/pom.xml`

验收标准：

- Maven 多模块可编译。
- `agent-api` 不依赖 `core/web`。
- `agent-core` 不依赖 `spring-boot-starter-webflux`。
- `agent-web -> agent-core -> agent-api` 依赖方向正确。

测试点：

- `mvn -pl source/htam-agent-platform -am test` 或等价构建命令。

### BE-02 配置与启动

目标：

- 实现 `agent-web` Spring Boot 启动类。
- 配置 `application.yml`、`application-dev.yml`。
- 支持 PostgreSQL、Flyway、MyBatis-Plus、LLM 配置。
- 敏感配置只放在 `source/htam-agent-platform/.env`，`application.yml` 和实施文档只引用变量名。
- 本地开发 PostgreSQL 连接通过 `.env` 提供：
  - `HTAM_DB_URL`
  - `HTAM_DB_USERNAME`
  - `HTAM_DB_PASSWORD`
- LLM 连接通过 `.env` 提供：
  - `HTAM_LLM_BASE_URL`
  - `HTAM_LLM_API_KEY`
  - `HTAM_LLM_MODEL_NAME`

涉及范围：

- `agent-web/src/main/java/...Application.java`
- `agent-web/src/main/resources/application.yml`
- `agent-web/src/main/resources/application-dev.yml`

验收标准：

- 后端应用可启动。
- 能通过 `.env` 中的 PostgreSQL 变量完成数据库连接。
- 缺少必要 LLM 配置时给出清晰配置错误。
- 配置项包含 `provider`、`apiMode`、`baseUrl`、`apiKey`、`modelName`、`stream`、`thinkingBudget`、`systemPrompt`。

测试点：

- 启动上下文测试。
- 配置绑定测试。

### BE-03 数据库迁移

目标：

- 创建三张核心表：
  - `agent_session`
  - `agent_message`
  - `agent_message_part`
- 创建必要索引和唯一约束。
- 迁移脚本默认通过 `.env` 中的 PostgreSQL 变量连接本地开发库并验证。

涉及范围：

- `agent-web/src/main/resources/db/migration/V1__init_agent_chat_tables.sql`

验收标准：

- 表结构与 `04` 详细设计一致。
- ID 使用 `varchar(64)`。
- `summary_message_id` 字段存在，语义为后续摘要边界。
- Flyway 脚本命名符合 `V版本号__描述.sql`。

测试点：

- Flyway migrate 成功。
- 重复执行不会破坏 schema。

### BE-04 API 契约与枚举

目标：

- 在 `agent-api` 中定义 DTO/VO、错误对象、枚举。

涉及范围：

- `AgentSession`
- `AgentMessage`
- `AgentMessagePart`
- `SessionStatus`
- `MessageRole`
- `MessageStatus`
- `PartType`
- `PartStatus`
- `QueueErrorCode`
- 统一错误响应对象

验收标准：

- `2xx` 返回业务数据。
- `4xx/5xx` 返回 `{code,message,traceId}`。
- 错误码覆盖 `UNAUTHORIZED`、`CONTENT_EMPTY`、`CONTENT_TOO_LONG`、`SESSION_BUSY`、`LLM_STREAM_FAILED`。

测试点：

- DTO 序列化字段名符合前端契约。

### BE-05 鉴权过滤器

目标：

- 实现 `X-Token`、`X-App-Code` 非空校验。
- 构造 `UserContext(token, appCode, appCode)`。
- 所有 API 都按 `userCode` 隔离。

涉及范围：

- `agent-web/security`
- `agent-api/common` 或 `agent-core/security`

验收标准：

- 缺少 `X-Token` 返回 `401`。
- 缺少 `X-App-Code` 返回 `401`。
- 日志不输出完整 token。

测试点：

- Web 层鉴权测试。
- token 脱敏测试。

### BE-06 会话接口

目标：

- 实现会话列表、新建、删除。

接口：

- `GET /api/agent/sessions`
- `POST /api/agent/sessions`
- `DELETE /api/agent/sessions/{sessionId}`

验收标准：

- 列表只返回当前 `userCode` 且 `status = active` 的会话。
- 列表按 `updated_at desc`。
- 新建默认标题为 `新对话`。
- 删除为软删除。
- 用户 A 不能删除用户 B 会话。

测试点：

- Service 单元测试。
- Controller 集成测试。

### BE-07 消息查询接口

目标：

- 实现历史消息查询。

接口：

- `GET /api/agent/sessions/{sessionId}/messages`

验收标准：

- 校验 session 属于当前用户且未删除。
- 消息按 `sequence asc`。
- parts 按 `part_sequence asc`。
- thinking 和 text 原样返回。

测试点：

- 查询归属校验。
- 消息与 parts 组装顺序。

### BE-08 LLM Provider 适配

目标：

- 实现 `LlmProviderAdapter`。
- V1 提供 `OpenAiCompatibleAdapter`。
- 隔离业务服务和 `agentscope-java` 调用细节。

涉及范围：

- `agent-core/llm/provider`

验收标准：

- 支持 `stream` 输出统一 `LlmStreamEvent`。
- provider 或 apiMode 无法解析时 fail closed，不静默回退。
- `agentscope-java` 阻塞或长耗时调用不阻塞 Netty 事件循环。

测试点：

- provider 解析测试。
- 配置错误测试。
- stream 事件映射测试。
- 真实大模型 smoke 测试：在 `.env` 提供有效 `HTAM_LLM_*` 时，调用实际模型并收到可解析的流式增量事件。

### BE-09 ContextAssembler

目标：

- 实现上下文组装组件。

涉及范围：

- `agent-core/llm/context`

验收标准：

- 只读取 `completed` 消息。
- user 取 text part。
- assistant 取 text part。
- thinking 不进入下一轮上下文。
- 当前用户消息追加在最后。
- system prompt 稳定，不在单轮内动态变更。

测试点：

- failed/streaming 消息不参与上下文。
- thinking 不参与上下文。
- 消息顺序正确。

### BE-10 流式发送接口

目标：

- 实现 `POST /api/agent/sessions/{sessionId}/messages/stream`。
- 返回 SSE `meta`、`thinking`、`message`、`done`、`error`。

验收标准：

- content 为空返回 `400 CONTENT_EMPTY`。
- content 超过 8000 字符返回 `400 CONTENT_TOO_LONG`。
- 写入用户消息和 text part。
- 自动标题取第一条用户消息前 30 字符。
- 创建 assistant streaming 消息。
- stream 正常完成后 assistant 为 `completed`。
- stream 失败后 assistant 为 `failed`，保存 `error_message`。
- agentscope 同一事件中同时出现 `ThinkingBlock` 和 `TextBlock` 时，分别发送 thinking/message。

测试点：

- SSE 事件格式。
- thinking/text 拆分。
- 失败态落库。

### BE-11 会话串行与断开处理

目标：

- 实现同一会话串行生成。
- 处理客户端断开和超时 streaming 清理。

验收标准：

- 同一 `userCode + sessionId` 并发第二个请求返回 `409 SESSION_BUSY`。
- 不同 session 可并行。
- 客户端断开时释放锁。
- 超时 `streaming` 消息被标记为 `failed`。

测试点：

- 并发请求测试。
- `doOnCancel()` 行为测试。
- 超时清理任务测试。

### BE-12 日志与脱敏

目标：

- 实现关键日志和脱敏策略。

验收标准：

- 覆盖鉴权失败、锁获取失败、流式开始/完成/异常、客户端断开、模型调用错误。
- 不输出完整 `X-Token`、`Authorization`、`apiKey`、完整请求头。
- 模型原始异常摘要化。

测试点：

- 日志脱敏单元测试。

## 4. 前端任务

### FE-01 工程骨架

目标：

- 创建 `source/htam-agent-platform-ui` Vue 3 + Vite 工程。
- 引入 Element Plus。

验收标准：

- 前端 dev server 可启动。
- Vite proxy 转发 `/api` 到后端。

测试点：

- 构建通过。

### FE-02 身份与请求封装

目标：

- 从 URL 读取 `token/appCode`。
- 写入 `sessionStorage`。
- API 请求统一带 `X-Token`、`X-App-Code`。

验收标准：

- URL 缺失参数时可从 sessionStorage 恢复。
- token/appCode 都缺失时进入鉴权失败态。
- 服务端返回 `401` 时清理本地身份状态。

测试点：

- authStore 单元测试。
- http 拦截器测试。

### FE-03 布局与基础状态

目标：

- 实现 ChatGPT 风格主布局。
- 实现欢迎态、鉴权失败态、基础错误态。

验收标准：

- 左侧会话栏、右侧主聊天区、输入框布局符合原型。
- 搜索框为禁用占位，不触发 API。
- 模型标签展示配置模型名，不写死具体模型。

测试点：

- 页面状态切换。

### FE-04 会话管理

目标：

- 实现会话列表、新建、切换、删除确认。

验收标准：

- 会话按更新时间倒序展示。
- 前端按本地日期分组：今天、昨天、过去 7 天。
- 删除需确认。
- 删除当前会话后切换到最近会话或欢迎态。

测试点：

- 会话 CRUD UI 流程。

### FE-05 消息展示

目标：

- 实现用户消息、助手消息、thinking、失败态。

验收标准：

- thinking 可折叠。
- 流式生成中 thinking 默认展开。
- 无 thinking 时不展示 thinking 区域。
- assistant failed 展示错误摘要和重试入口。

测试点：

- 不同消息状态渲染。

### FE-06 Fetch SSE 解析

目标：

- 实现 `fetch` 读取 `text/event-stream`。
- 支持 `meta`、`thinking`、`message`、`done`、`error`。

验收标准：

- `meta` 绑定 userMessageId / assistantMessageId。
- `thinking` 追加到 thinking part。
- `message` 追加到 text part。
- `done` 结束当前轮。
- `error` 标记助手失败。
- HTTP 非 2xx、JSON 解析失败、reader 异常进入失败态。

测试点：

- SSE parser 单元测试。
- 模拟错误事件测试。

### FE-07 排队与自动续发

目标：

- 实现响应中发送消息进入前端排队。
- 当前轮结束后自动发送队首。

验收标准：

- streaming 中发送不进入消息列表，不请求服务端。
- queuedPrompts FIFO。
- 排队消息可移除。
- 默认上限 10 条。
- 超过上限提示 `QUEUE_LIMIT_EXCEEDED`，不继续入队。
- 自动发送失败时进入失败态，不静默丢弃。

测试点：

- 连续排队 2 条并自动发送。
- 排队上限。
- 自动发送失败。

### FE-08 AbortController

目标：

- 实现切换会话、删除当前会话、刷新前清理时 abort 当前流。

验收标准：

- 每次流式请求创建 `AbortController`。
- 切换会话时调用 abort。
- `AbortError` 不重复弹普通模型错误。
- 当前未完成助手消息展示失败或已中断状态。

测试点：

- 切换会话中断流式请求。

## 5. 联调计划

### INT-01 基础链路

场景：

- `/?token=t1&appCode=app-a` 进入。
- 新建会话。
- 发送第一条消息。
- 使用 `.env` 中的真实 LLM 配置调用实际大模型。
- 收到 streaming thinking/message/done。
- 刷新后恢复历史消息。

验收标准：

- 会话、用户消息、助手消息、parts 都正确落库。
- title 自动生成。
- 真实模型返回内容可在前端展示，且刷新后从数据库恢复。

### INT-02 用户隔离

场景：

- app-a 创建会话。
- app-b 登录。

验收标准：

- app-b 看不到 app-a 会话。
- app-b 不能访问 app-a sessionId。

### INT-03 排队链路

场景：

- 模型响应中连续发送两条消息。

验收标准：

- 两条消息进入排队区。
- 当前轮完成后按顺序自动发送。
- 刷新前未发送排队消息不恢复。

### INT-04 异常链路

场景：

- 模型调用失败。
- SSE 中断。
- 客户端主动切换会话。

验收标准：

- assistant failed。
- errorMessage 保存。
- 会话锁释放。
- 输入区恢复。

### INT-05 并发链路

场景：

- 同一 session 并发调用流式接口。
- 不同 session 并发调用流式接口。

验收标准：

- 同一 session 第二个请求返回 `409 SESSION_BUSY`。
- 不同 session 可并行。

## 7. 风险与处理

| 风险 | 影响 | 处理 |
|------|------|------|
| agentscope stream 事件不是纯增量 | thinking/text 重复或丢失 | 适配层检测累计前缀，只取 delta |
| JDBC 阻塞 WebFlux 事件循环 | 性能和稳定性问题 | 数据库操作放到 boundedElastic、虚拟线程或专用执行器 |
| 客户端断开后模型仍运行 | token 浪费、锁不释放 | `doOnCancel()` 取消下游调用并更新状态 |
| 自动发送失败 | 用户消息丢失 | 失败消息进入消息列表并提供重试入口 |
| 鉴权 mock 被误用到生产 | 安全风险 | 文档和配置明确验证期用途，生产接入前替换真实鉴权 |

## 8. 开发入口建议

建议先从 M1 开始实施。M1 完成后，前端可以基于真实接口开发，不必等待模型流式链路完全完成。
