# 通用大模型对话需求

> 注意：本文档为历史阶段文档，仅作为需求、调研和演进参考。
> 当前 Agent 中台架构与后续开发以 `docs/v3-agent中台/` 为准。
> AI agent 执行开发任务前必须先阅读 `docs/README.md` 和 V3 架构文档。

## 1. 背景

建设一个基于 `agentscope-java` 的通用大模型对话 Web 端第一版，用于验证平台内大模型基础对话能力。

`source/agentscope-demo` 是已验证的参考实例，仅作为技术参考，不在其中进行修改。第一版实际开发采用前后端分离目录：后端为 `source/htam-agent-platform`，前端为 `source/htam-agent-platform-ui`。

## 2. 目标

第一版仅面向 Web 端，聚焦最基础的大模型对话体验：

- 用户可以进入通用对话页面。
- 用户可以创建、打开、删除自己的会话。
- 用户可以发送文本消息。
- 助手可以流式返回大模型回复。
- 用户可以在同一会话中进行多轮对话。
- 用户可以基于历史对话继续追问或补充问题。
- 大模型响应过程中，用户仍可以继续发送下一条消息；该消息先进入排队区，待当前回复完成后自动进入下一轮对话。
- 对话过程中可以展示大模型 thinking 内容，方便用户判断大模型的推理逻辑是否正确。
- 用户历史会话和消息可以按用户持久化保存。

## 3. 页面体验

页面风格参考 ChatGPT，采用经典对话布局：

- 左侧为会话侧边栏，展示历史会话和新建对话入口。
- 右侧为主聊天区，展示当前会话消息和输入框。
- 主聊天区需要区分展示用户消息、助手回复和 thinking 内容。
- thinking 内容应作为助手回复过程中的辅助信息展示，不能影响用户继续发送消息和阅读最终回复。
- thinking 内容为可选展示内容；当模型未返回 thinking 时，不展示 thinking 区域。
- 流式生成中 thinking 默认展开，回复完成后用户仍可查看，并可以手动折叠或展开。
- 当大模型正在响应时，用户发送的新消息不立即插入当前对话流，而是在输入框上方展示为排队消息，并带有明确的排队标识。
- 当前助手回复完成后，排队消息自动进入对话区并触发下一轮大模型回复。
- 排队消息属于前端临时状态，不在实际发送前持久化；页面刷新或关闭后未发送的排队消息会丢失。
- 用户可以移除尚未发送的排队消息。第一版建议限制排队数量，避免连续快速发送过多消息导致体验不可控。
- 第一版优先保证桌面端体验，移动端按侧边栏折叠思路预留。

## 4. 用户身份与鉴权

第一版不建设正式账号体系，采用调用方传入身份信息的方式完成用户隔离。

入口页面 URL 携带：

- `token`
- `appCode`

前端读取 URL 中的 `token`、`appCode` 后保存到浏览器会话状态，并在与服务端交互时转换为请求头：

- `X-Token`
- `X-App-Code`

后端第一版只做最小鉴权校验：

- `X-Token` 非空。
- `X-App-Code` 非空。
- 将 `appCode` 作为 `userCode` 的 mock 值。

所有会话和消息均按 `userCode` 隔离。

第一版鉴权仅用于内部验证和调用方联调，不构成生产级账号、租户或权限边界。生产接入前必须替换为真实鉴权与授权服务，并明确用户、应用和租户之间的隔离关系。

## 5. 会话能力

第一版提供基础会话管理能力：

- 新建会话。
- 查看当前用户的会话列表。
- 打开历史会话。
- 基于历史会话继续对话。
- 删除会话。
- 自动生成会话标题。

删除会话对用户表现为不可恢复，删除后该会话不再出现在普通会话列表中；后端可以采用软删除保留数据用于审计和排查。

自动标题第一版基于用户第一条消息直接截断生成，不额外调用模型；默认取前 30 个字符作为标题。

## 6. 消息能力

第一版支持文本对话：

- 用户在当前会话中发送文本消息。
- 服务端基于当前会话历史上下文调用大模型生成回复，支持多轮对话。
- 助手回复以流式方式返回前端。
- 对话过程中支持流式输出 thinking 内容。
- thinking 内容用于辅助用户理解大模型推理逻辑，用户可以据此判断回复过程是否合理。
- thinking 内容不是所有模型或所有回复都一定返回；无 thinking 时前端不展示 thinking 折叠区域。
- 大模型响应过程中再次发送的用户消息进入前端排队队列，不立即请求服务端。
- 当前回复完成后，前端按排队顺序自动发送下一条消息，形成连续多轮对话。
- 排队消息在进入实际发送流程前不写入数据库，刷新、关闭页面或浏览器会话丢失时不恢复。
- 用户可以从排队区移除尚未发送的消息；第一版默认排队数量上限为 10 条，超出时不再入队，并提示用户等待当前回复完成。
- 用户消息和助手消息均持久化保存。
- 重新打开历史会话时，可以恢复历史消息，并基于已恢复的上下文继续对话。

## 7. 非首版范围

以下能力不纳入第一版：

- 正式账号体系。
- 真实鉴权服务接入。
- 会话搜索。
- 会话置顶。
- 会话归档。
- 会话手动重命名。
- 停止生成按钮。
- 模型切换。
- 多模态输入输出。
- 历史会话检索。
- 跨会话长期记忆。
- 上下文压缩与自动摘要。
- 多入口接入（API、移动端、WebSocket 或消息渠道）。
- 移动端原生 App。
- 桌面客户端。
- Agent 工具管理。
- 插件化能力管理。
- 子 Agent 委派与多 Agent 编排。
- 定时自主任务或主动触发任务。
- 平台级 Agent 编排和管理能力。
